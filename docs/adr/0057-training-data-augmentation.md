# ADR 0057: 학습용 데이터 증강

- 상태: 채택
- 날짜: 2026-10-23
- 관련: ADR 0016·0025(재학습 루프), ADR 0010(상업 사용), ADR 0020(원본 접근), ADR 0055(공용 기하 변환
  `dlp_media.geometry`), ADR 0027(내보내기). 실영상 파일럿에서 본 1인칭 조건(젖은 손·반사광·움직임 흐림·
  초광각 왜곡).
- 계약 변경: 없음 (라벨·DB·내보내기 형식 그대로). 정책 `training.yaml augmentation`, 모듈 `dlp_train.augment`,
  `dlp_media.rle`(COCO 압축 RLE 부호화·복호화).

## 배경

재학습 루프(oracle-stub 학습기만 있음)에 실제 학습기를 붙일 때 1인칭 영상은 표본이 적고 조건(젖은 손,
스테인리스 반사, 빠른 손 흐림, 렌즈별 왜곡, 장착 방향 차이)이 넓다. 증강은 데이터를 늘리지만 라벨 변환이
틀리면 모델이 틀린 것을 배운다 (특히 좌우 뒤집기의 손 좌우, F-PAR-61에서 본 혼동). 또 증강이 판매 데이터나
골든셋 평가에 새면 안 된다.

## 결정

1. **한 곳의 기하 변환.** 증강 기하(좌우 뒤집기·회전·배율·자르기·원근)는 TTA와 같은 `dlp_media.geometry`
   3x3 투영 행렬을 쓴다. 이미지·박스·마스크·점이 같은 행렬로 움직인다. 렌즈 방사 왜곡(k1)은 같은 점 함수로
   이미지(역사상 고정점 반복)와 라벨을 옮긴다.
2. **라벨 종류별 규칙.** 박스·블러 박스는 옮긴 둘레의 외접 박스를 화면 안으로 자르고 남지 않으면 뺀다.
   마스크(RLE)는 최근접 보간으로 옮긴다. 2D 키포인트는 화면 밖이면 visibility 0. 좌우 뒤집기면 손 판정
   left↔right, COCO 17점 좌우 관절 번호 교환 (hand21 번호는 해부학 이름이라 그대로). 카메라 좌표 3D는
   뒤집기면 x 반전·손 개체 교환, 화면 가운데 중심 회전이면 같은 각도로 x·y 회전, 배율·자르기·원근·왜곡은
   3D를 바꾸지 않는다 (내부 파라미터가 바뀐 것). 주점이 화면 가운데가 아니거나 원근·왜곡이 있으면
   `geometry_3d_exact=False`로 표시한다.
3. **입력 경계.** 예제는 데이터셋 버전의 학습·검증 분할에서만 (골든·holdout이면 `AugmentationInputError`),
   픽셀은 라벨링 버킷 블러본에서만 (원본 버킷 저장소면 거부). 증강본은 메모리 안 학습 표본이며 라벨
   이력·DB에 쓰지 않는다.
4. **판매 내보내기에 넣지 않는다.** 내보내기(`dlp_export`)는 `dlp_train`을 import하지 않고(의존 표) 증강본을
   읽을 길이 없다. 증강 표본을 내보내는 옵션은 만들지 않았다. 나중에 만든다면 명시적 옵션이어야 하고
   manifest에 증강 레코드를 표시해야 한다 (이 ADR을 고쳐서).
5. **재현과 기록.** 정책(종류·세기·사본 수·seed)의 해시(`policy_digest`)가 학습 파라미터(`augmentation`)로
   들어가 모델 버전 태그와 MLflow 파라미터에 남는다. 표본마다 씨앗은 (seed, 표본 번호, 사본 번호)라 CPU에서
   결정적이다. oracle-stub 학습기는 산출물에 증강 해시·사본 수를 적는다 (실제 픽셀 학습기는 TODO(real-model)).

## 결과

- 실제 학습기가 붙으면 같은 함수로 증강한다. 라벨 변환은 합성 정답(흰 사각형·색 점)으로 변환마다 시험한다.
- 3D 근사(주점 가운데)와 원근·왜곡 때 3D 불변 가정은 정확하지 않다. 표시로 학습기가 그 표본의 3D 손실을
  끌 수 있다.
- 증강이 TTA와 같은 변환 집합을 쓰므로, TTA에서 불안정한 탐지는 증강으로 학습해 줄일 수 있는지 비교할 수 있다.
