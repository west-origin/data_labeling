# ADR 0003: 세션 수집과 미디어 처리

- 상태: 채택
- 날짜: 2026-10-07
- 관련: WP3

## 결정

1. **마스터 타임라인은 바디캠 PTS 시각이다.** 프레임 번호로 시각을 계산하지 않는다. PTS 인덱스는 패킷 PTS를 스트림 time_base 그대로 정수로 저장하고(`derived/<스트림>.pts.parquet`), ms 변환은 정수 곱 후 한 번만 나눈다. 가변 프레임레이트 합성 영상에서 변환 오차 0을 테스트로 확인한다.
2. **원본은 불변이고 수집은 멱등이다.** 원본 키(`sessions/<세션>/raw/<스트림><확장자>`)에 sha256을 함께 저장하고, 같은 내용이면 건너뛰고 다른 내용이면 거부한다. 파생 파일(PTS 인덱스, 프록시, 정규화 센서 파일)은 이미 있으면 다시 만들지 않는다. 인코딩 결과가 실행마다 바이트 단위로 같다는 보장이 없기 때문이다. DB의 세션도 같은 내용이면 그대로 두고 다르면 거부한다.
3. **프록시는 원본 PTS를 유지하고 오디오를 넣지 않는다.** 높이 480 이하, 1초마다 키프레임. 원본 영상에서 만들므로 원본 버킷에 둔다. 일반 라벨러용 영상은 블러 렌더본(WP5)이며 라벨링 버킷에 둔다.
4. **센서 스트림(IMU, 장갑)의 `uri`는 정규화된 Parquet을 가리킨다** (`t_ms` + 채널 열, 원 샘플레이트 유지). 원래 파일은 원본 키에 그대로 보관한다. 영상 스트림의 `uri`는 원본 영상이다.
5. **IMU는 기종별 추출기로 얻는다.** 바디캠 컨테이너에서 추출한 IMU는 바디캠과 같은 시계(`shared_clock`)다. 첫 추출기는 GoPro GPMF이며, 축 순서는 ORIN 태그를 따르고 없으면 ZXY로 본다. 카메라 앱이 따로 내보낸 CSV·Parquet도 읽는다.
6. **SeaweedFS 볼륨을 개발용으로 작게 잡는다** (`volumeSizeLimitMB=1024`, `volume.max=200`). 버킷마다 볼륨이 따로 잡히는데, 기본값(30GB)에서는 두 번째 버킷부터 쓰기가 실패했다. 서비스 스모크 테스트가 모든 버킷에 실제로 써 본다.
7. **세션 안 스트림 순서를 DB에 보존한다** (`streams.position`, 마이그레이션 0002).

## 확인이 남은 것

- GPMF는 KLV 파서, SCAL·ORIN 적용, 패킷 내 시각 배치까지 합성 바이트로 테스트했다. 일반 도구로는 MP4에 `gpmd` 트랙을 합성할 수 없어, **MP4에서 트랙을 꺼내는 부분은 실제 GoPro 파일로 확인해야 한다.**
- 실제 바디캠 파일의 `creation_time`이 시간대를 포함하는지 기종별로 확인해야 한다. 없으면 매니페스트의 `recorded_at`을 써야 한다.
