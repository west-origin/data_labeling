# ADR 0019: 공간 라벨 시각 규약과 2차 전체 검수 정정

- 상태: 채택
- 날짜: 2026-10-07
- 관련: WP13~WP15 뒤 전체 검수. 계약 형태 변경 없음 (규약 명문화, 데이터셋 스냅샷에 sessions.jsonl 추가)

## 1. 시각 규약

- **시간 구간 라벨**(행동·공백·상위 구간·손 상태·객체 상태·이벤트·관계·커버리지·설명)의 시각은 마스터
  타임라인 ms다.
- **공간 라벨**(박스·마스크·키포인트·블러 트랙, 3D 궤적)의 키프레임·표본 시각과 그 라벨의
  t_start_ms/t_end_ms는 **그 스트림 영상의 PTS 시각(스트림 시각) ms**다. 프리라벨·프라이버시 탐지·CVAT
  변환이 모두 이렇게 쓰고 읽는다. 다시 동기화해도(오프셋·드리프트·사람 미세 조정) 공간 라벨은 바뀌지 않는다.
- 기준 스트림(바디캠)은 동기화가 오프셋 0·배율 1로 두고 조정할 수 없으므로 두 시각이 같다.
- 다른 스트림의 공간 라벨을 마스터 타임라인에서 쓸 때는 `Stream.to_master_ms`로 바꾸고(착용자 매칭),
  마스터 시각에서 스트림 영상 프레임을 고를 때는 역변환한다(`dlp_export.frames.stream_ms`).
- 이전에 내보내기(COCO)만 공간 키프레임을 마스터 시각으로 보고 변환해, 오프셋이 있는 3인칭 스트림의
  주석을 버리거나 다른 프레임에 붙였다. 고쳤다.

## 2. 정정 (검수에서 찾은 결함)

검수자가 승인한 라벨 보존 (ADR 0015 보강)
- 행동(`dlp actions run`)과 관계(`dlp relations run`)도 버전·규칙이 바뀔 때 **검수 전인 것만** 지운다.
  행동은 검수된(또는 사람) 구간과 겹치는 새 구간을 버리고 빈 시간을 미상 공백으로 채워 타임라인 공백 0을 지킨다.

재실행과 정책 값
- 프리라벨 모델 버전에 정책 절 해시를 붙여 임계값·질의 등을 바꾸면 다시 돈다 (손·객체·OWLv2·전신·깊이·접촉).
  접촉은 버전이 바뀌면 검수 전 이전 접촉을 지운다. 착용자 매칭은 원래 트랙을 대체하므로 다시 하지 않는다.
- 배포된 재학습 모델이 기본 어댑터를 대신하면(replaces) 그 어댑터의 검수 전 라벨을 지운다 (중복 방지).
- 슬레이트 동기화 신뢰도를 config/policies/sync.yaml로 옮겼다.

프라이버시
- VLM(행동 분류)에는 블러본만 보낸다 (원본 프레임이 VLM 서버로 나가거나 설명 초안에 개인정보가 들어가지 않게).
- 사람이 승인한 블러 모델을 읽을 수 없으면 블러 탐지를 멈춘다 (조용히 기본 탐지기만 쓰지 않는다). 재학습
  모델 구간은 검수 우선 구간(trained_model)에 넣는다. 블러 모델 배포 정책은 approve만 허용한다 (검증기).
- OCR 탐지기가 없음을 TODO(real-model)로 표시했다 (WP5 계획과의 차이).

재학습 게이트·레지스트리 (ADR 0016 보강)
- replaces가 있는 과제는 배포 모델이 없을 때 **대신할 기본 어댑터들의 골든 예측 버전**(`--baseline-version`,
  여럿)과 비교해야 한다. 기본 어댑터보다 나쁜 모델이 첫 배포 기준만 넘어 대신하지 않게 한다.
- 후보 지표를 계산하지 못하면 게이트 실패다.
- 승인 대기 모델은 그 게이트 판정 뒤에 다른 모델이 배포됐으면 승인할 수 없다 (다시 평가).
- MLflow 레지스트리 별칭은 DB 커밋 뒤에 옮긴다.

액티브 러닝 (ADR 0017 보강)
- 수정률은 골든셋·사용 중지 세션을 빼고 센다 (골든 정답을 "추가"로 세어 부풀리지 않게).
- 큐레이션은 원본 버킷과 같은 버킷을 거부한다.

내보내기 (ADR 0018 보강)
- 데이터셋 스냅샷에 세션 메타데이터(sessions.jsonl)를 고정하고 내보내기는 그것을 쓴다 (같은 버전 = 같은 결과).
- 이력에는 실제로 쓴 세션만, 라벨 수는 그 형식이 실제로 쓴 라벨만 남긴다. 내보내는 동안 사용 중지가 생기면
  올리지 않는다. 이력을 먼저 쓰고 manifest.json을 마지막에 올린다 (manifest 없는 폴더 = 미완성).
- COCO 이미지는 블러본 프레임마다 하나다 (시각마다가 아니라).
- LeRobot: 3D 궤적은 그 스트림 것만, 겹치는 라벨은 검증 등급 높은·새 것부터, 검증 등급 묶음에 도구-표면 접촉·
  작업을 더했다, 영상 특징 이름은 정책 스트림을 따른다, 화면비가 다른 에피소드는 섞지 않는다.
- 원본 위치 검사는 모든 파일(바이트)을 본다.

## 3. 남은 것

- 종단 검증 테스트 `tests/test_end_to_end.py` (서비스 필요): 수집 → 동기화 → 블러 탐지·검수·승인·렌더 →
  프리라벨(stub) → 관계 → 행동(VLM stub, 블러본) → 검수 시뮬레이터(승인, 흔들린 박스·행동은 정답으로 수정) →
  데이터셋 버전(lakeFS) → 재학습(stub)·골든 평가·게이트(기본 어댑터 예측과 비교) → 내보내기(구간 JSON, COCO).
  내보낸 박스·행동이 픽스처 정답과 정확히 같고, 계보가 세션 → 버전 → 학습 실행 → 내보내기로 이어진다.
  행동 경계는 영상 접촉 휴리스틱만으로는 정답과 다를 수 있어(인접 동일 분류 병합 등) 검수 단계에서 고친다.
- 개발용 기본 비밀번호(dlp-dev-password)는 .env와 같은 개발 기본값이라 남긴다 (운영은 환경 변수로).
