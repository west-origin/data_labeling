# ADR 0033: 완료 탐지 세대와 검수 작업 연결·검수 계획 집계

- 상태: 채택
- 날짜: 2026-10-09
- 관련: WP1·WP5·WP6·WP11·WP12, ADR 0015·0023·0030·0032

## 문제

CLI 시작 시각을 완료 시각으로 쓰고 작업 생성 시각과 비교하면 모델 로딩 중 이전 탐지를 검수한
작업도 새 탐지를 승인한다. 전체 버전 이력으로 멱등 판정하면 v1→v2→v1 정책 복귀가 건너뛰어져
활성 결과가 v2에 남는다. 평가 가능한 일부 과제만 게이트에서 판단하면 요청한 다른 과제의 정답
부재를 놓친다. 검수 계획은 모든 세션 라벨과 모든 배정을 읽어 데이터량에 비례한 조회 비용이 든다.

## 결정

1. `PrivacyDetectionRun.model_versions`는 완료 세대의 **활성 모델 전체**다. 세션 잠금 아래
   추론이 끝난 실제 UTC 시각을 `at`에 쓰고, 최신 세대는 시각 대신 추가 일련번호로 고른다.
   멱등 판정은 최신 세대의 활성 버전 집합과 현재 요청 집합을 비교한다. 과거에 완료했다는
   사실만으로 비활성 버전을 건너뛰지 않는다. 모델 제거도 새 세대다.
2. 정책 복귀는 새로 추론한다. 과거 라벨 ID와 충돌하는 결과에는 새 탐지 ID를 이용한 파생 ID를
   부여한다. 과거 라벨·철회 기록을 덮어쓰지 않고, 사람이 검수한 블러는 계속 보존한다.
   외부 0건 표시는 아직 DB에 완료 기록이 없는 버전의 복구에만 사용한다.
3. `ReviewTask.privacy_detection_id`는 nullable 양수이며 완료 세대를 가리킨다. 0013의 복합 FK는
   탐지 ID·세션·스트림이 모두 일치하도록 강제한다. 작업 생성은 라벨·세대를 읽기 전에 세션을
   잠그고 외부 도구 작업과 DB 작업 생성이 끝날 때까지 유지한다. 배정 경유도 세션→배정 순서로
   잠가 수집과 순서를 맞춘다. 최신 세대에 연결된 수집 완료 표준·QA 작업만 승인·감사에 쓴다.
4. 기존 작업의 세대는 자동 추측·백필하지 않는다. DB 완료 기록이 없는 구 탐지에만 기존
   라벨 시각 비교를 유지한다. DB 완료 기록이 있으면 세대 없는 구 작업은 새 작업으로 대체한다.
   기존 APPROVED 세션을 이관 중 일괄 취소하지 않으며, 다음 재탐지부터 새 검수 세대가 필요하다.
5. 평가 게이트는 요청 모델 과제와 평가된 과제의 합집합을 판단한다. 요청 과제가 미평가면
   실패 이유를 JSON·Markdown·CLI에 남기고 전체 실패로 반환한다. 학습 루프도 같은 판정을 쓴다.
6. 프라이버시 세대 판정(`generation`), 렌더 검증(`rendering`), DB 잠금·탐지 이력·검수 저장소,
   검수 결과 마무리·품질 보고(`ops.results`)를 별도 모듈로 둔다. 기존 `runner`와 `repository`의
   공개 함수는 재수출해 호출자를 유지한다.
7. 검수 계획의 알려진 클래스·후보 담당자 부하는 DB에서 집계한다. 오류 삽입·측정 계보,
   수정·철회, 직접 검수 조건은 기존 운영 라벨 규약을 보존한다. 기존 배정은 대상 세션만 읽고,
   오류 삽입 원천이 다른 세션인 경우 후보 ID의 존재만 한 번에 확인한다.

## 검증·제약

실제 PostgreSQL로 모델 로딩 중 이전 검수, 탐지와 작업 생성의 경쟁, 반복 정책 복귀(0건/양성),
일부 요청 과제 정답 부재를 회귀 검사한다. SQLite·PostgreSQL 이관과 계약 왕복, 세대 복합 FK,
집계와 운영 이력 기준의 일치·오류 삽입 멱등을 검사한다. 합성 데이터로 같은 환경에서 집계 전후
쿼리 수와 시간을 측정한다 (`scripts/profile_review.py`). 실제 모델 추론·영상 처리 속도와 GPU
메모리는 이 측정 범위에 포함되지 않는다.

탐지·원본 검수 작업의 외부 호출 동안 세션 잠금을 유지하는 기존 정확성 경계를 보존한다. 잠금
구간을 단축하려면 추론 결과를 별도 작업 상태로 준비하고 게시 때 세대를 검증하는 설계가 필요하다.
