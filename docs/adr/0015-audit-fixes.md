# ADR 0015: 감사 뒤 정정 (보안·멱등성·평가 정확성)

- 상태: 채택
- 날짜: 2026-10-07
- 관련: WP5~WP12 전체 감사. 계약 변경: ReviewTask.sent_label_ids (Alembic 0006, `make schemas`)

## 배경

지금까지의 작업을 다시 검수해 잘못된 판단과 버그를 찾았다. 주요 원인은 (1) 확인하지 않은 가정
("GPU 필요", "CI 통과"), (2) 현재 라벨만 보고 재실행 여부를 정한 것, (3) 정책 값의 코드 고정이었다.

## 결정

1. **원본 영상 권한.** 블러(원본) 검수는 `config/policies/review.yaml reviewers.privacy`에 있는 원본 접근
   권한자에게만 배정한다 (계획·작업 생성 모두에서 검사, 위반 시 `AccessError`). 작업 라벨 계획의 오류 삽입
   원천에서 블러 단위를 빼고, 블러 검수는 일반 QA로 넘기지 않는다.
2. **모델 출처 라벨 ID에 버전 태그**(`dlp_schema.episode.version_tag`)를 넣는다 (프리라벨 예측기, 3D, 접촉,
   블러, 행동). 버전이 바뀌어 다시 돌리면 같은 단계의 이전 버전 중 **아직 검수하지 않은** 현재 라벨만
   삭제 레코드(`retractions`)로 지운다. 검수한 라벨은 남긴다.
3. **재실행 여부는 전체 이력으로 정한다.** 그 버전을 낸 적이 있으면 (검수자가 모두 고쳤거나 지웠어도)
   다시 만들지 않는다. 검수자가 지운 모델 제안이 되살아나지 않고, ID도 겹치지 않는다.
4. **검수 작업은 보낸 라벨 ID를 저장한다** (`ReviewTask.sent_label_ids`). 수집은 그 라벨과 비교하므로,
   작업을 만든 뒤 다른 단계가 라벨을 바꿔도 보내지 않은 라벨을 검수자가 지운 것으로 보지 않는다.
   배정 마무리는 그 배정의 작업이 모두 수집된 뒤 한 번만 한다. 시간 라벨 단위는 세션당 작업 하나다.
5. **평가는 운영 라벨이 아닌 레코드를 예측에서 뺀다** (오류 삽입 사본·측정 레코드와 그 후손).
   관계·커버리지처럼 바뀌지 않은 레코드는 옛 버전을 유지하는 모듈은 `--model relations=relations-*`로
   현재 레코드를 평가한다. 게이트의 허용 하락은 지표별로 줄 수 있고(`max_drop_by`, ms 오차용), 예측이 없으면
   ECE는 NaN이다 (만점이 아니다).
6. **표본 검수·오류 삽입 측정**: 검수 단위에는 도구가 보여 주는 종류만 넣는다 (정책 검사). 다른 단계가
   지운 표본은 판정에서 뺀다. 블러 삭제 발견은 검수자가 그 과제에서 남긴 레코드로만 판정한다.
7. **OWLv2 프라이버시 탐지기는 영상마다 캐시를 비운다** (`Resettable`). 앞 영상의 결과가 다음 영상에 쓰이던
   버그를 고쳤다.
8. **정책 값은 config로**: 접촉 출처별 신뢰도, 전신 추적 끊김, 3D 신뢰도, 평가 매칭 IoU, 검수 측정 허용
   오차·IoU, 블러 삭제 판정 겹침, QR·바코드 신뢰도, 반사면·OWLv2 문턱(코드 기본값 제거).
9. **모델 목록**: 외부 서버로 쓰는 VLM도 `config/models.yaml external`에 적어 라이선스 검사를 받는다.
   압축에서 꺼냈거나 직접 변환한 가중치는 실제 파일 해시를 모델 버전에 남긴다.
10. **CI**: 작업 브랜치 푸시에서도 돈다 (`main`이 없어 한 번도 실행되지 않았다). Label Studio 테스트는
    CVAT 없이도 돌고, CVAT 포함 서비스 테스트는 매일·수동 실행 작업에서 돈다.

## 정정한 판단

- SAM 2·SLAM·VLM은 "GPU 필요"가 아니었다. 셋 다 CPU로 돈다 (느릴 뿐). 남은 것은 연동 작업이다
  (`TODO(real-model)` 문구를 고쳤다).
- ADR 0005·0008의 "Hugging Face 접근 불가", "OWLv2 미연동"은 옛 상태였다 (갱신 표시를 달았다).
