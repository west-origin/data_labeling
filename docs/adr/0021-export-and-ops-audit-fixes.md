# ADR 0021: 내보내기·운영 지표·원본 접근 감사 정정 (3차 검수)

- 상태: 채택
- 날짜: 2026-10-07
- 관련: ADR 0018(내보내기), ADR 0020(운영 지표·감사·보관). 계약(dlp_schema) 변경 없음, 정책 YAML만 바뀜
  (`export.yaml ids`, `export.yaml lerobot.env.project`, `ops.yaml audit.service_purposes`)

## 결정

### 내보내기 (ADR 0018 보완)

1. **COCO 키포인트 범주의 박스만 주석**(예: 객체 person의 box_track)에도 `keypoints`(3*K개의 0)와
   `num_keypoints: 0`을 넣는다. COCO 키포인트 평가(pycocotools)는 그 범주의 모든 주석에서 두 필드를 읽는다.
2. **이력을 올리기 전에 따로 커밋한다.** `run_export`는 엔진을 받아 트랜잭션을 스스로 연다. 이력 트랜잭션에서
   내보낼 세션 행을 `FOR SHARE`로 잠그고 사용 중지를 다시 확인한다. 사용 중지(`withdraw_session`)는 세션 행을
   갱신하므로 둘은 직렬화된다: 사용 중지가 먼저면 내보내기가 실패하고, 내보내기가 먼저면 사용 중지의 계보 목록에
   이 내보내기가 보인다. 올리다 실패하면 이력과 manifest 없는 폴더(미완성 내보내기)가 남는다. 파일을 올린 뒤
   manifest 전에 사용 중지를 한 번 더 보고, 그 사이 사용 중지됐으면 manifest를 올리지 않고 실패한다.
3. **작업자·장소 ID 가명**: 가명 = HMAC(HMAC(비밀값, 내보내기 ID), "<종류>:<ID>"). 한 내보내기 안에서는
   일관되고(작업자 단위 분할 가능), 내보내기 사이에서는 이어지지 않는다. 비밀값은 `DLP_EXPORT_ID_SECRET`
   (export.yaml `ids.secret_env`, 내부 보관). 없으면 실행마다 임의 값이라 아무도 되짚을 수 없다.
   지금 작업자·장소 ID가 나가는 형식은 구간 JSON뿐이다 (COCO·LeRobot은 내보내지 않는다).
   (0027에서 보완: 세션·라벨 ID도 가명으로 바꾼다. 이 항목만으로는 같은 세션·라벨 ID로 내보내기를 이어 붙일 수
   있었다.)
4. **LeRobot 라벨 수**는 실제로 어느 프레임 특징에 들어간 라벨만 센다 (`Episode.used`).
5. **LeRobot 격리 환경을 잠근다**: `scripts/lerobot-env/`(pyproject + uv.lock, 작업공간 멤버 아님)에 전이
   의존성까지 버전·해시를 고정하고 `uv run --project scripts/lerobot-env --locked --isolated`로 돈다.
   torch·torchvision만 CPU판 인덱스(explicit)에서 받고 나머지는 PyPI에서 받는다 (`unsafe-best-match` 없앰).
6. **테스트 표시**: `services`와 `isolated_env`가 둘 다 붙은 테스트는 `make test-isolated`에서만 돈다
   (`make test-services`는 `services and not isolated_env`). 공식 로더 테스트는 PTS로 고른 블러본 프레임의
   내용(프레임마다 다른 밝기)까지 확인한다.

### 운영 지표·보관 (ADR 0020 보완)

7. **수정률·자동 승인율**에서 골든셋 세션과 사용 중지 세션을 뺀다 (dlp_active와 같은 기준).
8. (0027에서 바뀜: 단계별 파이프라인에서 너무 일찍 셌다) **검증 에피소드의 주**는 검증 완료 시각(`dlp_ops.metrics.verified_at`)으로 정한다: 후보 시각 T마다 T까지
   만든 레코드로 운영 현재 라벨을 구해 모델 라벨이 모두 T 이전에 검수(승인·수정·표본 검증)됐으면 완료, 그런
   T 중 가장 이른 것 (블러 제외). 그 뒤의 QA 수정·새 모델 버전·재검수는 이 값을 바꾸지 않아 지난 주의 수가
   나중에 바뀌지 않는다.
9. `dlp ops log-work --at <시각>`: 검수한 시각의 주에 센다 (기본 지금, 미래는 거부).
10. **원본 보관 기산점**은 마지막 사람 검수 변화(`review_changes`: 승인·수정·추가·삭제·표본 검증, 블러 포함)
    시각이다. 모델 버전 교체로 지운 레코드, 오류 삽입·측정 레코드, 검수 전 모델 라벨은 기산점을 늦추지 않는다.
    사용 중지 세션도 삭제 결정이 있으면 `delete_decided`로 보고 더 알리지 않는다.
11. **잔여 블러 감사자**는 그 스트림의 운영 현재 블러 트랙을 검수한 사람 모두와 달라야 한다 (CLI가 거부).
    기록의 `blur_reviewer`에는 트랙을 가장 많이 검수한 사람을 남긴다.

### 원본 접근 감사 (ADR 0020 보완)

12. 정적 검사가 `raw_bucket()` 호출·가져오기도 잡는다. `dlp ingest --no-db`(로컬 저장소만)도 감사 저장소를 쓰고
    기록을 `<로컬 저장소>/raw_access.jsonl`에 남긴다 (`raw_store_offline`).
13. 월간 리포트의 달 경계는 정책 시간대(`ops.yaml audit.timezone`)의 1일 0시다.
14. 서비스 계정이 파이프라인 용도(`ops.yaml audit.service_purposes`) 밖에서 원본에 접근하면 표시한다.

## 한계

- 실행자(actor)는 `DLP_ACTOR`(없으면 OS 사용자)로 **스스로 밝힌 값**이다. 사람이 서비스 계정 이름이나 다른
  사람 이름을 쓰는 것을 감사 기록만으로 막지 못한다. 1차 통제는 원본 버킷 자격 증명을 서비스 계정과 권한자에게만
  주는 저장소 접근 제어이고, 감사 리포트(14 포함)는 사후 확인이다.
- 검수 도구(CVAT)에 블러 검수용으로 올린 원본 프록시는 보관 만료 처리(`dlp ops retention`)가 찾거나 지우지
  않는다. 원본을 지울 때 그 세션의 원본 검수 작업도 운영 절차로 함께 지운다 (명령이 참고 문구로 알린다).
- 세션 ID는 가명 처리하지 않는다 (세션 ID에 작업자·장소를 넣지 않는 것이 수집 규약이다).
  → 0027에서 바뀜: 세션·라벨 ID도 내보내기마다 다른 가명이다.
