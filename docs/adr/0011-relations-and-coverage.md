# ADR 0011: 관계 도출과 표면 커버리지

- 상태: 채택
- 날짜: 2026-10-07
- 관련: WP9

## 결정

1. **관계는 YAML 규칙(`config/policies/relations.yaml`)으로만 만든다.** 규칙은 입력 구간(손 상태,
   도구-표면 접촉)의 필드 조건(`when`)과 관계 틀(`emit`)로 이루어지고, 규칙 ID가 관계의
   `derived_by`에 남는다. 같은 관계가 `merge_gap_ms`보다 짧게 끊기면 잇는다.
   - 손 파지 유형(power, hook, tool_grip 등) → grasp, palm_support → support,
     palm_push_wipe·비파지 → contact.
   - 도구-표면 접촉 → `도구(작용부) contact 표면`.
2. **도구-표면 접촉은 작용부 3D 점과 표면 평면 사이 거리로 찾는다.**
   - 작용부: 도구 클래스이고 part가 온톨로지 작용부인 `trajectory3d`.
   - 표면: surface 클래스 개체의 네 꼭짓점 궤적 (`part=corner_0~3`, corner_0 원점, 1 가로, 3 세로).
     새 계약 타입 없이 기존 `trajectory3d`의 part 이름 규약으로 표현한다.
   - 시각마다 꼭짓점으로 평면과 표면 좌표를 만들어 작용부 점을 (가로 비율, 세로 비율, 거리)로 바꾼다.
     같은 시각끼리만 비교하므로 카메라 좌표계여도 카메라 움직임과 무관하다.
   - 히스테리시스: 거리 ≤ on(1 cm)이면 시작, > off(2 cm)이거나 표면 밖이면 끝. 경계는 on 문턱 기준.
     손이 도구를 쥔 구간 안에서만 접촉으로 본다.
3. **커버리지는 접촉 중 작용부 경로를 도구별 반지름 원으로 쓸어 덮은 면적 / 표면 면적이다.** 연속
   샘플은 선분으로 이어 칠한다 (1 cm 격자). 도구·표면 쌍마다 `coverage` 레코드 하나를 접촉 전체
   구간에 둔다.
4. **재실행은 멱등이고 규칙을 바꾸면 차이만 반영한다** (`dlp relations run`). 레코드 ID는 내용의 해시,
   model_version은 `relations-<정책 해시>`다.
   - 내용이 같은 현재 레코드는 그대로 둔다 (정책이 바뀌어도).
   - 더 이상 나오지 않는 이 모듈의 현재 레코드는 삭제 레코드(retracted, parent)로 표시한다.
   - 이 모듈이 지운 내용이 다시 나오면 새 ID(`-1`, `-2`…)로 넣는다.
   - 검수자가 고치거나 지운 내용은 다시 넣지 않는다.

## 검증 (합성 걸레질 시나리오, `dlp_fixtures.wiping`)

- 접촉 구간 수 일치, 경계 오차 ≤ 70 ms (5개 seed, 실측 최대 약 65 ms).
- 커버리지 오차 ≤ 3%p (실측 약 1~1.5%p, 격자·잡음 때문에 약간 크게 나온다).
- 관계(손 파지 1 + 도구-표면 접촉)가 정답과 같다.
- 규칙 변경 → 해당 관계만 삭제 표시, 되돌리면 다시 생김, 재실행 시 변화 없음 (DB 통합 테스트).

## 한계

- 실제 영상에서는 작용부 3D 궤적과 표면 꼭짓점 궤적을 만드는 모듈이 아직 없다 (작용부·표면 마스크용
  SAM 2, 깊이·SLAM). 그때까지 도구-표면 접촉과 커버리지는 합성·사람 라벨에서만 나온다
  (`TODO(real-model)`, relations.yaml).
- 표면을 평면 사각형으로 본다. 변기 안쪽처럼 굽은 표면은 평면 여러 개나 메시가 필요하다.
- 지지·포함(support, contain) 관계 중 객체끼리의 것(탁자 위 컵, 양동이 속 걸레)은 아직 규칙 입력이 없다.
