# ADR 0037: 온톨로지 로딩·저장·계층·이관 검증 경계

- 상태: 채택
- 날짜: 2026-10-11
- 관련: WP1, ADR 0002·0028. Alembic 0014, 계약 검사, `make schemas`.

## 문제

사전 검증기가 DB 저장에서 호출되지 않고 일부 CLI는 v1 파일을 고정으로 읽었다.
구간의 자식 참조와 이관 목적지 ID도 형식 검증만 통과하면 잘못된 값이 남을 수 있었다.
검수 화면 프로젝트가 공통 이름을 사용해 서로 다른 사전의 선택지를 섞을 가능성도 있었다.

## 결정

1. 운영 사전은 DB `ontology_versions.content`가 기준이다. 공통 `get_ontology`와
   `get_session_ontology`로 등록 내용을 읽고 없는 버전·버전 없는 세션은 실패한다.
   프리라벨·행동·관계·검수·내보내기의 CLI 선택을 해당 세션/데이터셋 버전에 연결한다.
2. `insert_labels`는 모든 세션 잠금을 ID 순서로 얻은 뒤 배치 전체를 검증하고 INSERT한다.
   순수 규칙은 `label_validation`에 두고, 사전 값·세션 버전·저장 후 현재 구간 참조를 검사한다.
   QA `seeded_error`만 의미 오류를 허용한다. 운영 조회는 그 후손까지 제외한다.
   삭제 레코드는 부모 페이로드·버전을 유지해야 하며, 기존 잘못된 이력을 정리할 수 있다.
3. 0014는 PostgreSQL/SQLite에서 새 비삭제 라벨 INSERT의 세션 버전 일치를 검사한다.
   PostgreSQL은 세션 행 공유 잠금으로 버전 변경과 검사 사이의 경합도 막는다.
   기존 행을 덮어쓰거나 마이그레이션에서 의미를 추측해 고치지 않는다.
   DB 트리거는 사전 의미 전체를 검사하지 않으므로 운영 저장은 공통 함수를 사용한다.
4. `label_graph`는 자식의 action_id/segment_id 존재·중복·순환·계층·시간 포함을 검사한다.
   상위 구간은 자신보다 낮은 수준만 자식으로 삼는다. 하위 단계가 미정인 파일럿을 위해
   수준을 건너뛴 연결은 허용한다. DB는 상위 구간이 있을 때 노드 ID의 유일성을 요구한다.
   양손 행동(같은 action_id·다른 손 두 레코드, ADR 0002 §3)은 한 노드이며 두 손 레코드가 모두
   상위 구간 안에 있어야 한다. 같은 손에 같은 action_id가 겹치거나 segment_id가 다른 노드 ID와
   겹치는 것만 중복 위반이다 (F-SCH-01 정정: 처음 구현은 action_id 하나로 식별해 양손 행동을
   거부했다). 구간 없는 평가용 여러 모델의 예측은 같은 행동 ID를 유지할 수 있다.
5. `validate_episode`는 에피소드의 구조 검사에 사전·작업/하위 단계 소속·개체별 부분 검사를
   더한다. DB는 현재 박스/마스크/객체 상태에서 확인 가능한 클래스에 대해 부분 소속을 검사한다.
   클래스 미확인 개체의 도구 종류를 ID 문자열로 추측하지 않는다.
6. `migrate_labels`는 목적지 사전을 필수로 받고 결과를 의미 검증한다. 지원되지 않는 상태
   속성/값 변경이나 잘못된 목적지 ID는 `needs_review`로 돌려 잘못된 새 레코드를 게시하지 않는다.
   자식이 빠지는 등 결과 배치의 구간·부분 연결이 깨지면 이번 이관 배치를 재검수로 돌린다.
   이 함수는 저장·세션 버전 전환을 하지 않는다. 현재 전체 이관을 실행하는 CLI는 없다.
7. CVAT·Label Studio 프로젝트 이름에 사전 버전과 내용 해시를 넣는다. 초안 덧붙이기도 새
   선택지로 분리하고 기존 작업/프로젝트를 수정하지 않는다. 웹훅 등록은 구 프로젝트와 현재
   등록된 사전의 프로젝트를 조회한다. 새 프로젝트 생성 후 운영자가 웹훅 등록을 실행한다.
8. `dlp ontology audit`로 기존 운영 라벨의 위반을 읽기 전용으로 확인한다. 기존 위반을 자동
   삭제하지 않으며 사전 변경·실영상 판단은 별도 검수 후 이력 추가로 처리한다.

## 계약과 호환성

저장 필드와 JSON 구조는 바뀌지 않는다. 구간의 기존 `child_ids` 규칙을 강화했고, DB INSERT
트리거를 새 리비전에 추가했다. 이관 호출에는 `target_ontology=`가 필수다.
`ReviewSetup.ontology`는 구 호출자 호환을 위해 남기되 실제 사전 선택에는 사용하지 않는다.
기존 오류 데이터·구간 참조가 있는 운영 DB는 읽기 전용 감사 후 정리해야 한다.
저장 검증 때문에 무효 입력은 예전보다 일찍 실패하는 것이 의도한 변경이다.

## 한계

청소 하위 단계, 기술의 원시 동작 조합, 영상만으로 판단할 수 없는 소독 상태는 확정하지 않았다.
실제 영상 예시는 개인정보 검수 후 전문가가 용어 안내에 채워야 한다.
전체 이관의 원자적 세션 버전 전환·기존 검수 작업 재발행은 추후 별도 실행 경로가 필요하다.
현재 계약을 보존하는 구조 개선이며 실제 재학습기 연결이나 SaaS 인증 구현은 포함하지 않는다.
