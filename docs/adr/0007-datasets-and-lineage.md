# ADR 0007: 데이터셋 버전과 계보

- 상태: 채택
- 날짜: 2026-10-07
- 관련: WP7

## 결정

1. **데이터셋 스냅샷은 lakeFS에 커밋한다** (`config/defaults.yaml` infrastructure.data_versioning 기본값). 객체는 SeaweedFS의 `dlp-datasets` 버킷에, lakeFS 메타데이터는 내장 KV에 둔다. 스냅샷 URI는 `lakefs://저장소/커밋ID/datasets/<버전>`이라 커밋 이후 바뀌지 않는다. 오프라인 테스트용으로 내용 해시 기반 로컬 저장소도 둔다.
2. **스냅샷에는 포함 세션의 라벨 레코드 전체(수정 이력 포함)와 매니페스트를 넣는다.** 자동 원본과 사람 수정본의 차이가 그대로 재학습 데이터가 되기 때문이다. 오류 삽입 과제 레코드는 뺀다.
3. **분할 단위는 작업자와 장소다.** 골든·학습·검증 사이에 작업자나 장소가 겹치지 않는다. 작업자가 여러 장소를 오가 관계가 사슬처럼 이어지므로 다음 규칙으로 나눈다.
   - 골든 세션의 작업자·장소가 나오는 다른 세션은 `holdout`(어디에도 쓰지 않음)으로 둔다.
   - 검증 작업자를 하나씩 고르되, 매 단계 holdout이 가장 적게 늘어나는 작업자를 고른다. 학습·검증 경계에 걸친 세션도 holdout이다.

   빌드는 분할 뒤 교집합을 다시 검사하고, 하나라도 있으면 실패한다.
4. **골든셋은 도메인별 버전이다** (`golden_sets` 테이블). `dlp dataset golden`이 장소를 적게 공유하는 작업자부터 골라 제안하고, 사람이 확정한다. 확정된 골든셋은 학습에 쓰지 않는다.
5. **데이터셋 후보는 프라이버시 승인된 세션이다.** 사람 검증을 마친 세션은 빌드 때 생애주기를 분할 배정으로 옮긴다.
6. **사용 중지는 전파하되 과거 기록은 지우지 않는다.** 사용 중지된 세션은 이후 모든 데이터셋 버전(excluded_sessions에 기록)과 내보내기에서 자동으로 빠진다. 이미 만든 버전·학습 실행·내보내기는 재현성을 위해 그대로 두고, 계보 조회로 영향받은 목록을 돌려준다. 영향받은 모델은 다음 정기 재학습에서 다시 학습한다 (즉시 폐기 기준은 법무 검토).
7. **계보는 세션 → 데이터셋 버전(분할 배정) → 학습 실행 → 내보내기로 잇는다.** 내보내기 기록에는 실제로 내보낸 세션 목록을 남긴다.

## 합성 데이터에서 본 분할 비용

합성 세션 300개(작업자 24명, 장소 16곳, 작업자당 장소 1~3곳)에서 골든 20개 남짓과 검증 10%를 고르면, 겹침 0을 지키는 대가로 holdout이 8~26% 나왔다. 실제 현장에서 작업자가 오가는 장소가 많을수록 holdout이 커진다.

## 확인이 남은 것

- 실제 작업자·장소 분포에서 holdout 비율을 보고 검증 비율·골든셋 크기를 조정해야 한다. holdout이 너무 크면 분할 단위를 "장소 그룹"(같은 기관 등)으로 바꾸는 것도 검토한다.
- lakeFS는 개발 환경에서 root로 실행한다 (이름 있는 볼륨 권한). 운영에서는 디렉터리 권한을 맞추고 기본 사용자로 실행한다.
