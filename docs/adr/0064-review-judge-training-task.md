# ADR 0064: 검수 판정 모델 학습 과제 (`aireview`)

- 상태: 제안 (구현 전, 사내 GPU 학습 서버와 판정단 후보 실측 전)
- 날짜: 2026-10-29
- 관련: ADR 0040(AI 1차 검수, I9: AI ok는 사람 검수를 줄이지 않음, 사내 서버만), ADR 0060(공개 데이터와 우리 데이터의
  2단계 경계), ADR 0062(실제 학습기·판정 표시 보정), ADR 0063(판정단, 이 ADR은 그 "검수 판정 모델 학습" 절을 구체화한다),
  ADR 0016·0025(재학습 루프·레지스트리).
- 계약 변경: 이 제안 자체는 없음. 구현 때 `training.yaml tasks.aireview`, 예제 추출, 격리 학습 환경, `models.yaml` 항목이
  필요하다 (아래 "구현 범위").

## 배경

AI 판정과 사람의 처리는 이미 쌓인다: `ai_review_units`(판정·이유·제안·요청 본문 해시), `ai_review_exposures`(그 작업에
판정을 보였는지, 대조군), `ai_review_outcomes`(라벨마다 사람 결과 `AiHumanAction`과 AI 판정의 연결), 라벨 이력(사람의 최종
라벨). 사용자는 의사결정 모델·Qwen의 시행착오와 사람 검수를 학습에 써서 판정 모델이 나아지기를 원한다. 재학습 루프
(`dlp train run`)에는 프리라벨·행동·프라이버시 과제만 있고 판정 과제가 없다.

## 결정

1. **과제 `aireview`를 학습 루프에 더한다.** 다른 과제와 같은 흐름(데이터셋 버전 → 예제 추출 → 학습 → 골든 평가 →
   게이트 → 배포)을 쓴다. 배포는 사람 승인만이다(`deploy: approve`): 판정은 검수자 화면을 바꾸기 때문이다.
2. **정답은 사람의 최종 판단만.** 예제 하나 = (라벨, 판정 요청과 같은 맥락·블러본 프레임, 사람 결과).
   - `approved` → ok, `corrected`·`deleted`·`replaced` → wrong(고친 내용이 있으면 제안 정답으로), `stale`·`na` → 뺀다.
   - 오류 삽입 레코드(정답을 아는 틀림)는 사람이 찾았든 못 찾았든 wrong 정답으로 쓸 수 있지만, 운영 라벨이 아니므로
     예제에 넣을 때 그 표시를 남기고 학습·평가 분할 규칙(작업자·장소 단위)을 그대로 따른다. 블라인드·이중 측정 레코드는
     뺀다 (`current_labels()` 규칙).
   - AI 판정·이유는 정답이 아니다. 입력 특징(같은 모델이면 넣지 않음)이나 "틀린 예" 표시로만 쓴다. AI 판정을 정답으로
     삼으면 AI의 습관을 다시 배운다.
3. **데이터 경계.**
   - 예제는 데이터셋 버전의 학습·검증 분할 세션에서만 뽑는다 (`dlp_train.extract`, 골든셋·holdout 제외, F-ETA-19).
   - 프레임은 지금 승인된 블러본만 (`dlp_aireview.media.open_blurred`와 같은 게이트, 렌더 해시 확인). 원본 버킷은 쓰지 않는다.
   - 학습은 사내 GPU에서만 한다 (우리 데이터, ADR 0060 2단계, Colab·Kaggle 금지).
4. **편향 관리.** AI 판정을 본 검수자(arm `shown`)의 판단은 그 표시에 끌려갈 수 있다.
   - 평가·게이트 지표는 대조군(`holdout`)만으로 계산한다 (ADR 0040의 품질 지표와 같은 규칙).
   - 학습 예제에는 arm을 기록하고 대조군 예제의 가중치를 정책으로 둔다 (`training.yaml tasks.aireview.params`).
   - 학습 모델이 다시 검수자 화면에 나가므로 대조군 비율(`review.yaml ai_review.holdout_ratio`)을 줄이지 않는다.
5. **출발 가중치와 라이선스.** 판정단 후보(ADR 0063) 중 가중치 라이선스가 미세조정·파생 모델 사용을 허용하는 것만 출발
   가중치로 쓴다. 결과 모델은 `models.yaml`에 `base_model`로 출발 가중치를 적고 그 분류를 물려받는다 (ADR 0062 A.9,
   `make licenses`). 학습 데이터는 우리 검수 데이터라 공개 데이터셋 목록(`external_datasets.yaml`)에 없다.
6. **게이트.** 후보 모델의 골든셋 판정은 DB에 쓰지 않는다 (`dlp aireview eval`, 메모리). 지금 판정 버전과 비교해
   대조군 기준 ok 놓침률 95% 상한이 나빠지지 않고, 지적 정밀도·재현율과 ECE가 `evaluation.yaml`의 판정 게이트 기준을
   넘어야 승인 후보가 된다. 통과해도 사람이 승인해야 `aireview.yaml backend.panel`(또는 `backend.model`)에 올라간다.
7. **배포 형태.** 학습 결과는 사내 vLLM이 읽는 가중치(병합 가중치 또는 LoRA 어댑터)다. 판정단의 한 모델로 넣어 지금
   모델과 병렬로 판정하고(ADR 0063 불일치 신호), 대조군 지표가 쌓인 뒤에 기본 모델을 바꾼다.

## 구현 범위 (후속)

- `dlp_train.extract`에 `aireview` 예제 추출 (outcomes·exposures·라벨 이력 결합, 분할·운영 라벨 규칙).
- 격리 학습 환경 `scripts/judge-train-env/`(uv.lock, YOLOX 환경과 같은 방식)과 학습기 `trainer: judge-lora`(CPU stub 포함,
  TODO(real-model)).
- `dlp aireview eval`을 학습 루프 게이트로 부르는 연결, `evaluation.yaml` 판정 게이트 기준.
- 배포 승인 시 `aireview.yaml` 패치 미리보기(콘솔 가져오기와 같은 방식, 설정 파일은 사람이 고친다).

## 결과

- 판정 모델이 사람의 검수 결과로 나아지는 길이 생긴다. 사람 검수·표본은 줄지 않고(I9), 평가는 대조군만이라 자기 강화
  편향을 지표가 잡는다.
- 사내 GPU 학습 서버와 판정단 후보 실측(ADR 0063)이 먼저 필요하다.
