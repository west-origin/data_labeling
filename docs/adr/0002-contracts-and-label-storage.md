# ADR 0002: 계약 타입과 라벨 저장 방식

- 상태: 채택
- 날짜: 2026-10-07
- 관련: WP1

## 결정

1. **계약 타입은 Pydantic v2 모델로 정의하고 JSON Schema를 생성해 저장소에 둔다** (`schemas/`). 모든 모델은 알 수 없는 필드를 거부하고(`extra="forbid"`) 생성 후 변경할 수 없다(`frozen`). 생성 파일이 코드와 다르면 `make check`가 실패한다.
2. **라벨 하나는 `LabelRecord` + 종류별 페이로드(`kind`로 구분)다.** 공간 라벨은 프레임별 레코드가 아니라 키프레임을 가진 트랙(box_track, mask_track, keypoint_track, blur_track)으로 저장한다. CVAT 트랙과 대응되고 레코드 수가 줄어든다.
3. **행동은 손별 원시 동작으로 저장한다.** 양손 행동은 두 손 레코드가 같은 `action_id`를 가진다. 기술·하위 단계·작업은 `segment`(level로 구분)로 원시 동작을 묶는다. 행동 레코드의 구간은 접근 시작~종료와 같아야 한다.
4. **사이 구간(대기·미상·범위 외)은 `gap` 레코드로 채운다.**
5. **라벨은 불변이다.** 수정은 새 레코드 + `parent_label_id`, 삭제(오탐 제거)는 `retracted=True` 레코드로 표현한다. 예외는 검수 상태(verification_state, reviewer_id, reviewed_at)로, 승인할 때마다 레코드를 복제하지 않도록 이 열만 갱신을 허용한다. PostgreSQL 트리거가 그 밖의 UPDATE와 DELETE를 막는다.
6. **온톨로지 대조 검증은 스키마 검증과 분리한다** (`check_label`). 계약 타입은 온톨로지 버전과 무관하게 같고, 값의 유효성은 라벨이 가리키는 온톨로지 버전으로 판정한다.
7. **온톨로지 이관은 매핑 표(rename/removed)로 새 버전의 새 레코드를 만들고 검증 상태를 미검수로 되돌린다.** 골든셋은 이관 후 재검수해야 평가에 쓸 수 있다는 기준 문서 원칙을 따른다. 상태 속성·값의 이름 변경은 아직 지원하지 않는다.
8. **모든 datetime은 시간대 정보가 있어야 한다** (`AwareDatetime`).
9. **DB 테이블은 SQLAlchemy Core로 정의하고 Alembic으로 마이그레이션한다.** 페이로드는 JSONB, 검색에 쓰는 열(세션, 종류, 시각, 검수 상태, 출처)은 별도 열로 둔다.

## 결과

- 다른 패키지는 `dlp_schema` 타입으로만 데이터를 주고받는다.
- 계약 변경은 이 ADR을 갱신하거나 새 ADR을 쓰고, 마이그레이션·계약 테스트·JSON Schema를 함께 바꾼다.
