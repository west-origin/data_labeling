# ADR 0017: 액티브 러닝 (세션 선택과 FiftyOne)

- 상태: 채택
- 날짜: 2026-10-07
- 관련: WP14. 계약 변경 없음 (DB·JSON Schema 그대로). 공용 모듈 `dlp_schema.history` 추가.

## 결정

1. **세션 점수의 첫 항목은 클래스별 검수자 수정률 하나다** (기준 문서: 처음부터 가중합을 쓰지 않는다).
   점수 = 검수 대기 모델 라벨마다 그 클래스의 수정률을 더한 값 = 예상 수정 수. 수정률 30%인 시트 접기를
   담은 세션이 0.5%인 컵 옮기기만 담은 세션보다 먼저 나온다.
2. **수정률은 개별 검수만 센다**: 사람 승인(그대로)·사람 수정·사람 삭제(오탐)·사람 추가(놓침, 정책으로 끔).
   표본 검증 상태는 표본만 본 것이라 세지 않는다. 오류 삽입·측정 레코드와 그 후손은 빠진다.
   클래스 키는 `라벨 종류/클래스`다. 검수 수가 적은 클래스는 전체 수정률 쪽으로 당기고
   (`(고침 + w × 전체) / (검수 + w)`), 처음 보는 클래스는 전체 수정률을 쓴다.
3. **검수 변화 분류(`dlp_schema.history.review_changes`)를 재학습(WP13)과 같이 쓴다.** 재학습 예제와
   수정률이 같은 규칙(무엇을 고침·추가·삭제로 보는지)을 따르게 한다.
4. **점수 항목은 플러그인이다** (`dlp_active.terms.register_term`). 정책 `score.terms`에 이름과 가중치를 적어
   켠다. 지금 등록된 것: correction_rate(켜짐), uncertainty(Σ(1-신뢰도), 신뢰도 보정 확인 뒤 켬). 이후 모델 간
   불일치·신규성·희소 클래스·임베딩 다양성을 같은 방식으로 붙인다.
5. **후보 세션**은 프리라벨이 끝나고 사람 검수 전인 세션이다. 골든셋 세션(사람이 처음부터 라벨링)과 사용
   중지 세션은 뺀다. 블러는 점수에 넣지 않는다 (종료 조건 전까지 전수 검수). 세션 안의 검수 순서는
   우선순위 큐(ADR 0014)이며 이 점수와 별개다.
6. **FiftyOne은 분석용 사본이다.** 고른 세션의 **블러본(라벨링 버킷)만** 받아 동영상 데이터셋을 만들고,
   라벨 시각을 블러본 PTS 인덱스로 프레임에 맞춘다(허용 오차 1 ms, 프레임 사이 키프레임은 버림). 각 라벨에
   검증 상태·출처·모델 버전·label_id를, 샘플에 점수·순위·기여 상위 클래스를, 데이터셋 info에 클래스별
   수정률을 넣는다. FiftyOne 프레임 번호는 FiftyOne 안에서만 쓴다.
7. **FiftyOne은 선택 설치다** (`make install-curation`, 약 1 GB). Apache-2.0이고 내장 MongoDB는 내부 분석
   도구로만 쓴다 (배포하지 않는다). FiftyOne이 opencv-python-headless를 요구해 기존 contrib판과 cv2가 겹치므로
   override로 contrib판 하나로 통일한다. CI 검사 작업은 이 그룹을 설치해 FiftyOne 왕복 테스트까지 돈다.

## 결과

- `dlp active rank [--limit] [--json]`, `dlp active fiftyone [--limit] [--name] [--cache]`.
- 완료 기준 테스트: 합성 수정률 분포(시트 접기 30%, 대걸레 10%, 컵 0.5%)와 임의 분포에서 세션이 예상 수정 수
  순서대로 선택된다 (`packages/active/tests/test_select.py`).
