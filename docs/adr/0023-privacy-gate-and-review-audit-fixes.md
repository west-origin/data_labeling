# ADR 0023: 프라이버시 게이트·검수 연동 감사 정정

- 상태: 채택
- 날짜: 2026-10-07
- 관련: WP5(프라이버시), WP6·WP12(검수 연동·운영), ADR 0019, ADR 0020. 계약(dlp_schema)·DB 변경 없음.

## 결정

1. **블러 검수 화면 좌표.** 블러 라벨은 원본 화소 좌표이고 CVAT 블러 검수는 480p 프록시를 올린다.
   CVAT로 보낼 때 (프록시/원본) 비율로 곱하고 받을 때 나눈다. 원본 해상도는 감사 저장소의 서명 URL로
   헤더만 읽고(안 되면 내려받아) 정한다. 고치지 않은 라벨의 비교 기준은 왕복 값 `quantize(label, scale)`.
2. **렌더 보간.** 블러본은 CVAT와 같이 키프레임 사이를 선형 보간한다 (다음 키프레임이 outside면 유지).
3. **승인 조건.** 영상 스트림마다 마지막 자동 탐지(모델 출처 블러 레코드의 최신 시각) 뒤에 만든 운영
   블러 검수 작업(표준·QA)을 수집했어야 승인한다. 탐지가 0개여도 사람이 영상을 본 작업이 있어야 한다.
4. **승인 뒤 블러 변경.** 재탐지나 블러 검수 수집으로 운영 블러가 바뀌면 `privacy_state`를 auto_blurred로
   되돌린다 (생애주기는 되돌리지 않는다). 블러본 옆에 `<스트림>.render.json`(블러 라벨 ID 집합 + 렌더 정책
   해시)을 두고, 해시가 다르면 다시 렌더한다.
5. **블러 검수 담당자.** `create_privacy_tasks`는 담당자를 필수로 받고 `review.yaml reviewers.privacy`에 있어야
   만든다. grant 감사 기록은 원본 프록시를 CVAT에 올리기 전에 남긴다 (ADR 0020 "접근 전에 기록").
6. **수집하는 검수자 = 작업 담당자.** 웹훅의 도구 사용자 ID(Label Studio 숫자 ID)를 검수자로 쓰지 않는다.
   CVAT 작업 담당자가 다르면 받지 않는다.
7. **Label Studio 프리라벨은 예측(prediction)** 으로 올린다. 사람이 제출한 주석이 없으면 수집하지 않는다.
   서비스 계정이 만든 주석의 웹훅은 무시한다. 다른 종류로 바꿔 붙인 구간은 삭제 + 추가로 본다.
8. **멱등·잠금.** 배정 작업 생성은 배정 행을 `SELECT … FOR UPDATE`로 잠그고, 이미 작업이 있으면 그것을
   돌려준다. 수집은 작업 행을 잠그고 상태를 본다.
9. **보낸 뒤 지운 라벨**에 대한 검수 결과(승인·수정·삭제)는 반영하지 않는다 (되살아나지 않게).
10. **오류 삽입 블러 삭제 발견**은 같은 스트림, 그 배정에서 새로 그린 블러(수집 때 ID에 배정 사본 접두사)로만
    인정한다. 주입 기록 detail에 배정 ID를 둔다.
11. **나뉜 트랙 사이 틈.** 같은 대상 블러가 없는 틈이 `privacy.yaml tracker.split_review_ms` 이하이면
    track_gap(detail=split) 검수 우선 구간으로 낸다.
12. **잔여 누락 감사.** `dlp privacy audit-sample [--week]`가 그 주 승인된 블러본에서 표본을 뽑고 검수 방식을
    판정한다. 감사가 없는 주는 통과로 보지 않는다 (`review_mode`의 None).

## 남은 일

- `dlp_ops` 주간 지표는 감사가 없는 주의 잔여 누락을 비워 두어 경고가 나지 않는다. "감사 없음"을 경고로
  내야 한다 (dlp_ops 담당).
- `tests/test_end_to_end.py`는 블러 검수 작업 없이 승인하므로 3번 조건에 맞춰 수집한 작업 기록을 넣어야 한다.
