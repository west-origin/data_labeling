# ADR 0012: 행동 구간 2단 구조

- 상태: 채택
- 날짜: 2026-10-07
- 관련: WP10

## 결정

1. **경계는 신호가, 분류는 VLM이 맡는다.** VLM은 긴 클립에서 시간 경계를 잘 잡지 못한다.
   - 1단 (`dlp_actions.boundaries`): 손목 속도(손바닥 길이/초, 해상도와 무관)와 접촉 구간으로 경계 후보를 만든다.
     - 접촉 시작·끝 (장갑 또는 손 상태)
     - 정지(`still_speed` 미만이 `min_still_ms` 이상)의 시작·끝
     - 접촉 밖 속도 골짜기 (앞뒤 최고 속도의 `valley_ratio` 이하): 멈추지 않고 다음 목표로 바꾸는 순간.
       접촉 중에는 문지르기 왕복이 골짜기를 많이 만들어 쓰지 않는다.
   - 2단 (`dlp_actions.vlm`): 후보 구간마다 VLM이 원시 동작·사이 구간 종류·대상·한 문장 설명을 JSON으로 낸다.
2. **VLM 출력은 온톨로지 안으로 강제한다.** 프롬프트에 목록을 넣고, JSON Schema(enum)를 서버에 넘기고
   (OpenAI 호환 `response_format=json_schema`), 받은 뒤에도 다시 검사한다. 위반하면 위반 내용을 붙여
   `max_retries`번 다시 묻고, 그래도 안 되면 미상(gap unknown)이다. 모르는 구간을 대기로 두지 않는다.
3. **병합·채우기.** 같은 분류의 인접 구간은 병합한다. 단, 병합 구간에 접촉이 둘 이상이면 같은 대상에
   같은 행동을 연달아 한 것이므로 접촉 사이 경계(골짜기 우선)에서 나눈다. 행동 사이는 대기·미상·범위 외로
   채운다. 후보 구간이 전체를 나누므로 타임라인 공백이 없다. 접촉 시각은 구간 안에서 접촉 신호가 바뀌는
   시각이고, 접촉 중에 시작한 구간은 접촉 유지다.
4. **재실행은 멱등이다** (`dlp actions run`). model_version은 `actions-<정책 해시>+<VLM 버전>`이고,
   버전이 바뀌면 이전 버전의 현재 레코드를 삭제 표시한 뒤 새로 쓴다.
5. **VLM 서버가 없으면 행동 구간을 만들지 않는다.** 전부 미상으로 채우면 검수 부담만 늘기 때문이다.
   CPU·CI는 정답 기반 stub(`OracleVlm`, 오류 응답 주입 가능)을 쓴다.
6. **VLM은 상업 사용 가능한 가중치를 쓴다** (ADR 0010). 기본 후보 Qwen2.5-VL-7B-Instruct(Apache-2.0).
   같은 계열 3B는 비상업 연구 라이선스라 쓰지 않는다.

## 검증 (합성 행동 시퀀스)

- 경계 후보 재현율 99.8% (30개 시퀀스, 기준 문서 허용 오차: 접근·종료 ±200 ms, 접촉 ±70 ms). 완료 기준 ≥ 95%.
- 오라클 VLM이면 행동 순서(동사·대상)가 20개 시퀀스 모두 정답과 같고, 경계는 대부분 허용 오차 안이다.
- 타임라인 공백 0, 설명은 행동마다 하나.
- 합성 생성기의 "옮기다" 이동 거리를 30~70 px로 고쳤다. 몇 px만 옮기는 경우는 정지와 구분할 수 없어
  어떤 신호 기반 방법으로도 경계를 찾을 수 없었다.

## 한계

- 실제 VLM 품질은 VLM 서버(GPU의 vLLM, 또는 CPU의 llama.cpp)를 띄워 골든셋으로 평가해야 한다 (WP11).
  요청 형식만 테스트했다. (ADR 0015 정정: 처음에 "GPU 필요"라고 적었으나 CPU 서버로도 된다.)
- 손 키포인트가 없는 손(화면 밖)은 행동 구간을 만들지 않는다.
- 기술·하위 단계(SegmentPayload) 묶음은 아직 만들지 않는다.

## 갱신 (ADR 0019)

2차 전체 검수 정정이 이 결정을 보강한다. 바뀐 내용은 ADR 0019를 따른다.
