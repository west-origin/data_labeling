# ADR 0034: 웹훅 실패 응답과 영상 표시 회전 검사

상태: 채택 (2026-10-09)

## 배경

웹훅 수집의 `TaskError`를 콜백 안에서 잡으면 부분 변경이 커밋되고 HTTP 204가 반환될 수 있었다.
본문 크기·읽기 시간·연결 스레드 수에도 제한이 없었다. 스마트폰 영상은 인코딩된 1920×1080 픽셀에
-90° 표시 행렬을 붙여 세로 영상으로 재생할 수 있지만 PyAV 추론·프록시는 인코딩된 픽셀을 썼다.
프록시에서 표시 행렬이 사라져 검수자가 보는 방향과 원본 플레이어의 방향이 달라질 수 있었다.

## 결정

- 콜백은 수집 예외를 트랜잭션 밖으로 전달한다. 커밋/의도적 무시 후에만 204를 응답한다.
  담당자 불일치는 403, 그 외 수집 실패는 503과 `Retry-After`를 응답한다.
- `review.yaml` 형식 버전 2의 `webhook` 절로 바인드 주소·본문 상한·읽기 시간·동시 연결 상한·재시도
  안내 시간을 정한다. 모호한 길이/청크 전송은 거부한다. 연결마다 독립된 처리 스레드를 쓰되 상한을 둔다.
- JSON 형태와 작업 ID를 인증 이후에도 검증한다. 실패 로그에는 작업 키와 예외 종류만 남긴다.
- `probe`는 첫 프레임의 표시 회전을 읽고 CLI에 출력한다. PyAV 19 이상을 요구한다.
- 수집은 모든 영상의 표시 회전을 원본 업로드 전에 검사한다. 회전이 있으면 명시적으로 거부한다.
  프록시 직접 생성도 동일하게 거부한다. 원본과 프록시 중 한쪽만 회전시키지 않는다.
- 계약/DB 행 형식은 바꾸지 않는다. 영상 입력 정책과 HTTP 실패 응답의 변경이다.

## 한계와 운영

표시 회전이 없는 정규화 사본을 별도로 준비하고 원본을 보존한다. PTS·프레임 수·메타데이터를
검사해야 하며, 기존 세션의 미디어/좌표는 자동 변환하지 않는다. 회전 태그 지원의 완성은 원본 보존,
정규화본의 출처와 변환, 캘리브레이션/좌표 일관성을 함께 설계해야 한다.

서버는 영속 작업 큐가 아니다. 도구의 재시도 지원/설정을 확인하고, 누락 사건은 수동 `review collect`로
복구한다. 운영 배포에서는 TLS·요청 속도 제한·헤더 전체 수신 제한을 갖춘 게이트웨이와 방화벽을 둔다.
Python 서버의 유휴 타임아웃과 연결 상한만으로 모든 느린 헤더 공격을 막지는 않는다.
과부하 연결은 본문을 읽기 전에 503을 보내고 닫는다. 본문 전송 중인 클라이언트에서는 연결 오류로
보일 수도 있으므로, 운영 게이트웨이 및 클라이언트의 연결 오류 재시도도 확인한다.

## 검증

실제 루프백 HTTP 요청으로 인증·JSON·크기/길이·느린 본문·동시 연결 상한·503 후 재시도를 검사한다.
실제 SQLite 트랜잭션에서 CLI 콜백의 중간 쓰기가 수집 실패 시 롤백됨을 확인한다. 합성 MP4의
±90°/180° 표시 행렬을 읽고, 회전 입력의 프록시/수집이 파일 생성·업로드 전에 거부됨을 확인한다.
