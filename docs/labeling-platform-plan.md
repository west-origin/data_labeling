# 1인칭 돌봄 영상 라벨링 플랫폼 구축 계획 (개정본)

2026-10-07

## 개요와 목표

청소·요양돌봄·간호 작업자의 가슴 바디캠 1인칭 영상을 로봇 모방학습용 데이터로 라벨링하는 오픈소스 기반 플랫폼을 만든다. 라벨은 작업 단계부터 원자 행동, 양손 접촉·파지, 도구와 표면의 접촉까지 기록하며, 자동 라벨링 모델은 사람 검수 결과로 계속 재학습된다.

**도메인 우선순위는 청소다.** 플랫폼과 스키마는 세 도메인을 모두 받도록 설계하되, 모델 개발과 온톨로지 검증은 청소 → 요양돌봄 → 간호 순서로 확장한다. 청소는 물체·도구 조작 중심이고, 요양돌봄은 사람 몸을 다루는 상호작용이, 간호는 안전·의료 맥락과 더 엄격한 프라이버시가 더해져 난도가 단계적으로 오르기 때문이다.

플랫폼이 갖출 기능은 다음 일곱 가지다.

1. 자동 객체탐지와 온톨로지 기반 행동 기록
2. 자동 스켈레톤(착용자 손, 타인 전신, 3인칭 영상이 있으면 착용자 전신)
3. 얼굴(반사면 포함)·택배 송장·문서·가족사진 등 자동 블러
4. 모든 자동 결과의 사람 검수와 수정
5. 검수 결과로 각 자동 모델이 향상되는 학습 루프
6. 3인칭 영상, 바디캠 IMU, 촉각장갑 데이터의 선택적 동기화
7. 로봇 학습 포맷으로의 내보내기

성공 기준은 세 가지다. 영상 1시간당 검수 시간이 분기마다 줄어들 것, **검수 후 잔여** 블러 누락이 목표치 이하일 것, 라벨러 간 행동 경계 일치도가 기준을 넘을 것. 구체 수치는 파일럿 결과로 Gate 0에서 잠정치를 정하고, Phase 1 수동 라벨링 결과로 Gate 1에서 확정한다.

## 핵심 설계 원칙

- **프라이버시 게이트가 맨 앞이다.** 블러 검수를 마친 영상만 일반 라벨러에게 간다. 원본은 원본 권한자(블러 검수자, 표정 라벨러)와 학습 서버만 접근한다.
- **모든 자동 결과는 라벨로 저장한다.** 블러, 박스, 스켈레톤, 행동 구간 모두 수정 가능한 레코드이며 영상을 덮어쓰지 않는다. 수정 이력은 그대로 재학습 데이터가 된다.
- **온톨로지는 코드보다 먼저, 버전으로 관리한다.** 상위 계층은 고정하고 하위 클래스만 추가한다. 모든 라벨에 온톨로지 버전을 기록한다.
- **로봇이 따라 할 수 있을 만큼 물리적으로 기록한다.** 행동마다 사전·사후 상태, 접촉 시점, 파지 유형, 양손 역할을 남기고, 도구를 쓰는 행동은 도구와 표면의 접촉까지 남긴다.
- **모든 시간 값은 시각(ms)으로 다룬다.** 바디캠이 가변 프레임레이트일 수 있으므로 허용 오차, 유지 시간, 경계를 프레임 수가 아니라 PTS 기준 시각으로 정의한다.
- **선택 스트림은 목록으로 설계한다.** 3인칭 영상, IMU, 촉각장갑은 세션의 스트림 목록에 있거나 없을 뿐이며, 없을 때도 파이프라인이 그대로 동작한다.
- **검수는 전수가 아닌 우선순위 큐로 운영한다.** 단, 블러는 누락이 사고이므로 정해진 종료 조건을 충족할 때까지 전수 검수한다.
- **개선은 고정 골든셋으로만 판정한다.** 골든셋은 작업자·장소 단위로 학습 데이터와 분리하며, 새 모델은 골든셋에서 기존 모델을 넘을 때만 배포한다.
- **검수 결과 자체를 의심한다.** 프리라벨이 검수자를 끌고 가는 편향을 블라인드 과제와 오류 삽입 과제로 정기 측정한다.

## 전체 파이프라인 구조

모든 자동 결과는 사람 검수를 거쳐 모델 재학습으로 돌아온다.

1. 입력: 1인칭 바디캠(항상, 기준 스트림) / 바디캠 IMU(선택, 카메라 지원 시) / 3인칭 영상(선택, 착용자 전신용) / 촉각장갑(선택, 접촉 정답 신호)
2. 수집·동기화: 세션 마스터 타임라인, 오프셋·드리프트 보정
3. 프라이버시 게이트: 얼굴·반사면·송장·문서·사진물·화면 자동 블러 → 원본 권한자가 검수 → 잔여 누락 표본 감사
4. 자동 프리라벨: 객체·도구 추적, 손·전신 스켈레톤, 접촉·파지(손·도구), 카메라 자세·깊이, 행동·상태
5. 작업 라벨 검수: 블러본만 열람, 우선순위 큐, 블라인드·오류 삽입 과제, QA 샘플 검수
6. 데이터셋 버전: 수정 이력 포함, 작업자·장소 단위 골든셋 분리
7. 재학습·평가: 골든셋에서 기존 모델과 비교 → 통과 시 배포
8. 로봇 학습 내보내기: COCO, 구간 JSON, 에피소드 (데이터셋 버전에서 출력, 검증 상태 정책 적용)

재학습된 모델은 두 곳으로 돌아간다. 블러 탐지기는 프라이버시 게이트로, 객체·포즈·접촉·행동 모델은 자동 프리라벨로 배포된다.

## 데이터 모델과 멀티스트림 동기화

세션 하나에 마스터 타임라인 하나를 두고, 바디캠을 기준 스트림으로 삼는다. 다른 스트림은 오프셋과 클럭 스케일 두 값으로 기준 시각에 매핑한다.

| 스트림 | 존재 | 원본 저장 | 표시용 변환 |
| --- | --- | --- | --- |
| 1인칭 바디캠 | 항상 | 원본 MP4 + PTS 인덱스 | 블러 렌더본(오디오 제거), 프록시 영상 |
| 바디캠 IMU (자이로·가속도) | 선택 (카메라 지원 시) | 영상 메타데이터(예: GPMF)에서 추출해 Parquet, 원 샘플레이트 | 영상과 같은 시계이므로 별도 동기화 불필요 |
| 3인칭 영상 | 선택 | 원본 MP4 + PTS 인덱스 | 블러 렌더본(오디오 제거) |
| 촉각장갑 (좌·우) | 선택 | Parquet 또는 HDF5, 원 샘플레이트 | 영상 프레임 시각으로 리샘플 |
| 오디오 | 영상에 포함 | 원본, 접근 통제 저장 | 동기화 계산용으로만 사용, 배포본에서 제거 |

세션 메타데이터에는 바디캠 장착 위치, 카메라 내부 파라미터(렌즈 왜곡 포함), 카메라-IMU 외부 파라미터, 장갑 기종과 캘리브레이션 값을 기록한다. 장착 위치는 바뀔 수 있으므로 캘리브레이션은 세션 단위로 연결한다.

**카메라 선정 기준.** 바디캠은 IMU를 영상과 같은 시계로 기록하는 기종을 우선한다. 가슴 캠은 몸 움직임이 크고 요양 현장에는 움직이는 사람이 많아 영상만으로는 SLAM이 실패하기 쉬운데, IMU가 있으면 시각-관성 SLAM으로 안정성이 크게 오른다.

**동기화는 세 단계로 시도한다.**

1. 시각 슬레이트: 촬영 시작과 종료 때 시각을 인코딩한 QR 코드를 휴대폰 화면에 띄워 모든 카메라로 찍는다. QR을 자동 검출해 각 영상의 PTS와 절대 시각을 맞춘다. 대부분의 바디캠은 NTP·PTP를 지원하지 않으므로 이 방식을 기본으로 한다. 기기 시각은 참고값으로만 기록한다.
2. 이벤트 동기화: 슬레이트 직후 장갑 낀 손으로 탁자를 두 번 두드린다. 두 영상의 오디오 피크와 장갑 압력 스파이크를 자동 검출해 맞춘다. 장갑에는 오디오가 없으므로 장갑 동기화는 이 이벤트가 기본 수단이다.
3. 신호 상관: 이벤트가 없으면 영상끼리는 오디오 상호상관으로, 장갑은 손 키포인트 운동(또는 IMU)과 압력 변화의 상관으로 오프셋을 구한다. 장갑의 상관 기반 동기화는 신뢰도가 낮으므로 검수 화면에서 반드시 사람이 확인한다.

시작과 종료 두 지점 이상에서 맞춘 뒤 선형 보정으로 클럭 드리프트를 제거한다. 바디캠은 가변 프레임레이트일 수 있으므로 프레임 번호가 아니라 PTS로 처리한다. 자동 동기화 결과는 검수 화면에서 사람이 미세 조정할 수 있고, 조정값, 사용한 동기화 방법, 신뢰도를 세션 메타데이터에 남긴다.

촬영 현장 프로토콜(QR 슬레이트, 두드림 신호, 장갑 착용 확인, IMU 기록 설정 확인)은 Phase 0에서 문서화해 작업자에게 교육한다.

## 마스터 데이터 스키마: 에피소드 그래프

모든 라벨은 하나의 에피소드 그래프로 묶여 저장되고 내보내진다. 에피소드는 세션 안의 하위 단계 하나 이상에 해당하며, 네 층으로 구성된다.

| 층 | 내용 | 예시 | 생성 방식 |
| --- | --- | --- | --- |
| 개체 | 손, 객체, 도구, 사람, 고정 표면의 개체 ID와 속성 | 오른손_01, 걸레_12, 세면대_02 | 탐지·추적 자동, 사람 확인 |
| 관계 | 개체 사이의 접촉·지지·포함 관계와 그 구간. 손-객체 접촉과 도구-표면 접촉을 모두 포함 | 오른손_01 → 파지 → 걸레_12, 걸레_12 → 접촉 → 세면대_02 | 접촉 구간과 상태에서 자동 도출, 사람 확인 |
| 이벤트 | 원시 동작 → 기술 → 작업의 시간 구간 | 잡다 → 닦다 → 세면대 청소 | 프리라벨 후 사람 수정 |
| 상태 전이 | 객체별 상태의 시간 순서와 표면 커버리지 | 세면대_02: 오염 → 깨끗함, 커버리지 85% | 프리라벨 후 사람 수정 |

관계는 사람이 직접 그리지 않는다. 라벨 비용을 늘리지 않도록 접촉 구간, 객체 위치, 상태에서 규칙으로 도출하고 검수자는 틀린 것만 고친다.

### 도구 접촉과 표면 커버리지

청소의 핵심 동작은 손이 아니라 도구가 표면에 닿는 것이다(걸레가 바닥에, 솔이 변기에). 따라서 도구 객체에는 작용부(걸레 헤드, 솔 끝, 스펀지 면)를 정의하고 다음을 기록한다.

- **도구-표면 접촉 구간:** 작용부가 표면에 닿아 있는 구간. 손-도구 파지 구간 안에 놓인다.
- **작용부 궤적:** 작용부 중심의 3D 궤적(카메라 자세·깊이 모듈 출력 사용).
- **표면 커버리지:** 작용부 궤적을 표면 평면에 투영해 계산한 처리 영역 비율.

"오염 → 깨끗함" 같은 상태는 영상만으로 판정하기 어려우므로, 커버리지를 상태 전이 판정의 보조 근거로 함께 저장한다.

### 라벨 공통 메타데이터

모든 라벨(박스, 키포인트, 접촉, 행동, 상태, 3D 좌표, 블러)에 다음 필드를 붙인다. 구매자가 관측 사실과 모델 추론을 구분할 수 있게 하기 위해서다.

| 필드 | 값 |
| --- | --- |
| 출처 | 사람, 모델(모델 버전), 센서(장갑 등) |
| 근거 | 관측(화면에서 직접 확인), 추론(간접 판단), 미상 |
| 신뢰도 | 0~1 |
| 검증 상태 | 미검수, 표본 검증(샘플링 검수를 통과한 구간에 속한 자동 라벨), 사람 승인, 사람 수정 |
| 좌표계 (3D만) | 카메라, 작업자 몸, 공간(SLAM 지도) |
| 3D 출처 (3D만) | 단안 깊이, 시각 SLAM, 시각-관성 SLAM, 다시점 보정 |

**내보내기 검증 정책.** 기본 내보내기에는 사람 승인, 사람 수정, 표본 검증 라벨만 포함하고 검증 상태를 그대로 표시한다. 미검수 라벨은 명시적 옵션으로만 포함한다. 블러 라벨은 예외 없이 사람 검수를 거친 것만 배포본 렌더링에 쓴다.

"깨끗함" 같은 상태는 사람이 판단해도 주관이 섞이므로, 상태마다 판정 기준을 가이드라인에 문장과 예시 이미지로 정의한다.

## 프라이버시 게이트: 자동 블러와 검수 루프

수집·동기화 직후 블러 자동 탐지와 블러 검수를 끝내야 다음 단계로 넘어간다. 블러 영역은 트랙 라벨로 저장하고, 배포 영상을 만들 때 강한 모자이크나 단색 채움으로 렌더링한다. 약한 가우시안 블러는 쓰지 않는다. 배포 영상에서는 오디오 트랙을 기본 제거한다.

| 대상 | 탐지 방법 | 블러 범위 |
| --- | --- | --- |
| 얼굴 (작업자, 대상자, 사진·화면 속 얼굴) | 얼굴 전용 탐지기, 초기 검수 데이터로 파인튜닝 | 얼굴 박스 + 여유 20% |
| 반사면 속 사람 (거울, 유리, 꺼진 화면) | 오픈 보캐뷸러리 탐지("mirror")로 반사면 영역을 찾고, 그 안에서 얼굴·사람 탐지 임계값을 낮춰 적용. 가슴 캠은 착용자 얼굴이 거울에서만 보이므로 화장실 청소에서 필수 | 반사면 속 얼굴 박스 + 여유 20%, 얼굴 판별이 어려우면 반사면 속 사람 전체 |
| 택배 송장 | 오픈 보캐뷸러리 탐지("shipping label") + OCR 텍스트 영역 + 바코드·QR 탐지 결합 → 전용 탐지기로 전환 | 송장 전체 |
| 문서·우편물 (고지서, 편지, 처방전 등) | 오픈 보캐뷸러리 탐지("document", "envelope") + OCR 텍스트 밀도 → 전용 탐지기로 전환 | 문서 전체 |
| 화면 (TV, 휴대폰, 모니터에 표시된 내용) | 오픈 보캐뷸러리 탐지("screen", "phone") + 켜짐 여부 판별 | 켜진 화면 전체 |
| 가족사진 (액자, 벽·탁자 사진) | 오픈 보캐뷸러리 탐지("photo frame", "photograph") → 전용 탐지기로 전환 | 사진물 전체 |
| 주소 식별 정보 (문패, 호실 번호) | OCR 텍스트 영역 + 오픈 보캐뷸러리 탐지("door plate") | 표지 전체 |
| 확장 후보: 약봉투, 환자 팔찌, 침상 명패, 의료 차트, 명찰, 메모 | 같은 방식, 범위는 미결정 사항 참조 | 대상 전체 |

**시간적 안정화.** 탐지 결과를 추적기(ByteTrack 또는 SAM 2)로 트랙으로 묶는다. 끊긴 구간은 보간하고, 트랙 소실 후에도 200ms 이상 블러를 유지한다. 임계값은 재현율 우선으로 낮게 잡는다.

**블러 검수.** 검수 화면은 누락 찾기에 맞춘다. 트랙 끊김 구간, 경계 신뢰도 구간, 탐지기 간 불일치 구간, 반사면이 화면에 있는 구간을 먼저 보여주고, 빠른 스크러빙과 영역 추가 도구를 제공한다. 추가(누락)와 삭제(오탐)를 따로 기록해 각 탐지기 재학습에 쓴다.

**잔여 누락 감사.** 실제 위험은 검수 후에도 남은 누락이다. 승인된 블러본에서 매주 무작위 표본(예: 승인 영상의 5%)을 뽑아 원 검수자가 아닌 감사자가 독립적으로 재확인하고, 그 결과로 영상 1시간당 잔여 누락률을 추정한다. 성공 기준과 Gate 1 기준은 이 잔여 누락률로 판정한다.

**전수 검수 종료 조건.** 잔여 누락률이 목표치 이하인 상태가 연속 일정 기간(예: 8주) 유지되면 블러 검수를 우선순위 큐 + 표본 검수로 전환한다. 잔여 누락률이 다시 목표를 넘으면 즉시 전수 검수로 돌아간다. 새 도메인(요양, 간호)에 진입할 때는 전수 검수부터 다시 시작한다.

**학습용 원본 접근.** 라벨링은 블러본에서 하고, 객체·포즈 모델 학습은 접근 통제된 서버에서 원본으로 한다. 이 방식은 수집 동의 범위와 맞아야 하므로 법무 검토를 받는다.

## 자동 프리라벨: 객체·온톨로지·스켈레톤·접촉

프리라벨은 여섯 모듈이 만들고, 결과는 모두 신뢰도와 함께 저장한다.

| 모듈 | 초기 방식 (데이터 없음) | 성숙 후 방식 | 출력 |
| --- | --- | --- | --- |
| 객체·도구 탐지·추적 | 오픈 보캐뷸러리 탐지 + SAM 2 마스크 추적, 도구는 작용부 마스크 별도 추적 | 도메인 파인튜닝 탐지기 | 객체 트랙(클래스, 개체 ID, 마스크), 도구 작용부 마스크 |
| 손 스켈레톤 | 손 포즈 모델, 21관절 | 1인칭 데이터로 파인튜닝 | 좌·우 손 키포인트 |
| 타인·착용자 전신 | RTMPose / RTMW (3인칭 영상 있으면 착용자 포함) | 같은 모델 파인튜닝 | 전신 키포인트, 대상자 자세 |
| 접촉·파지 | 손: 장갑 있으면 압력 임계값으로 접촉 구간 자동 분할, 없으면 손-객체 거리·마스크 겹침으로 추정. 도구-표면: 작용부 마스크와 표면의 겹침·깊이 차로 추정 | 영상 기반 접촉 분류기 학습 (장갑 세션 정답 + 맨손 사람 라벨) | 손별 접촉 구간, 접촉 대상, 파지 유형, 도구-표면 접촉 구간 |
| 카메라 자세·깊이 | 렌즈 왜곡 보정 → IMU 있으면 시각-관성 SLAM, 없으면 시각 SLAM + 단안 메트릭 깊이 | 같은 구성, 3인칭 영상으로 교차 검증 | 바디캠 6자유도 궤적, 손·객체·작용부 3D 좌표, 처리 표면의 평면 추정(커버리지 계산용) |
| 행동·단계 구간 | 2단 구조: ① 손 키포인트 속도와 접촉 신호로 경계 후보 구간 생성 ② VLM이 각 후보 구간을 온톨로지 목록 안에서 분류하고 사전·사후 상태와 설명을 JSON으로 출력 | 시간적 행동 분할 모델 학습 | 단계·행동 구간, 사전·사후 상태, 한 문장 설명 |

**VLM은 경계를 정하지 않는다.** VLM은 긴 클립에서 시간 경계를 잡는 정확도가 낮다. 경계는 운동·접촉 신호가 제안하고, VLM은 분할된 구간의 분류와 설명만 맡는다. 인접 후보 구간이 같은 행동으로 분류되면 병합한다.

**장갑 세션은 접촉 모델의 교사이지만 분포 차이를 관리한다.** 장갑 압력으로 얻은 접촉 정답으로 영상 기반 접촉 분류기를 학습하면 장갑 없는 세션의 프리라벨 품질이 오른다. 다만 촉각장갑을 낀 손은 맨손과 외형이 다르고, 장갑이 동작 자체를 바꿀 수 있다. 이를 위해 다음을 지킨다.

- 맨손 세션에서 사람이 접촉 시점을 라벨링한 세트를 학습과 골든셋에 모두 둔다.
- 접촉 분류기 지표는 장갑 세션과 맨손 세션으로 나눠 보고하고, 배포 판정은 맨손 지표를 기준으로 한다.
- 가능하면 얇거나 맨손과 외형이 비슷한 촉각장갑을 고른다.
- 같은 작업을 장갑·맨손으로 각각 촬영한 쌍 세션을 일부 확보해 동작 차이(속도, 파지 유형 분포)를 측정한다.
- 간호 도메인에서는 감염관리 때문에 촉각장갑 착용이 어려울 수 있으므로 Phase C 진입 전에 착용 가능 여부를 확인한다.

**착용자 전신은 3인칭 영상이 있는 세션에만 둔다.** 1인칭만으로는 품질이 낮으므로, 없는 세션에서는 비워둔다.

**카메라 자세와 깊이.** 로봇 학습에는 손 궤적이 화면 좌표가 아니라 몸 또는 공간 기준 3D 좌표로 필요하다. IMU가 있는 세션은 시각-관성 SLAM으로 스케일과 궤적을 안정적으로 얻고, 없는 세션은 시각 SLAM과 단안 메트릭 깊이 추정을 결합한다. 3D 출처 필드에 어느 방식인지 기록해, IMU 유무에 따른 품질 차이를 구분할 수 있게 한다.

**3인칭 영상 속 착용자 식별.** 3인칭 영상에는 여러 사람이 찍히므로 바디캠 착용자를 먼저 찾아야 한다. 동기화된 시각에서 1인칭 손 움직임(또는 IMU 운동)과 3인칭 각 인물의 손목·몸통 궤적을 비교해 자동 매칭하고, 검수자가 확인한다.

**장갑 낀 손.** 촉각장갑이나 의료용 장갑을 낀 손은 일반 손 포즈 모델의 정확도가 떨어진다. 장갑 착용 영상을 초기 검수 데이터에 의도적으로 포함해 파인튜닝한다.

## 사람 검수 워크플로와 품질관리

검수는 권한과 숙련이 다른 네 단계로 나눈다.

1. **프라이버시 검수** (원본 접근 권한자): 블러 수정, 동기화 확인. 승인 시 블러본이 생성된다.
2. **표정 라벨 패스** (원본 접근 권한자, 요양돌봄 Phase B부터): 대상자의 표정 기반 불편 반응 이벤트 기록. 얼굴 표정은 블러 이후 보이지 않으므로 원본 권한이 필요하지만, 누락 찾기와 표정 해석은 숙련이 다르므로 블러 검수와 별도 패스·별도 담당자로 운영한다. 청소 도메인에서는 비활성화한다.
3. **작업 라벨 검수** (일반 라벨러, 블러본만): 객체, 도구 작용부, 스켈레톤, 접촉·파지, 도구-표면 접촉, 행동·단계 구간, 상태, 설명 문장, 실패·안전 이벤트 수정.
4. **QA 샘플 검수** (선임): 무작위 5~10% 재검수, 오류 유형 집계, 가이드라인 갱신.

**검수 도구 구성.** 공간 라벨(박스, 마스크, 키포인트, 블러)은 CVAT, 시간 구간과 영상·장갑·IMU 시계열 동기 재생은 Label Studio를 쓰는 하이브리드를 기본안으로 한다. 두 도구 사이에 공통 세션 스키마로의 변환 계층을 둔다. 다만 두 도구를 장기 운영하면 ID와 버전 동기화 비용이 계속 들므로, 단일화 여부를 Gate 1의 결정 항목으로 둔다. 유력안은 CVAT를 기본 작업대로 두고 시간 구간·촉각 검수 화면만 자체 개발하는 방식이다.

**우선순위 큐.** 낮은 신뢰도, 모델 간 불일치, 신규 객체, 장갑 신호와 영상 접촉 추정이 어긋나는 구간을 먼저 배정한다. 높은 신뢰도 구간은 샘플링 검수하며, 통과한 구간의 자동 라벨은 "표본 검증" 상태가 된다.

**일치도 측정.** 전체의 약 5%는 두 명이 독립 라벨링한다. 행동 경계는 허용 오차 내 일치율, 파지 유형·신체 부위·상태는 카파 계수로 측정한다. 낮은 항목은 가이드라인 예시를 보강한다.

**프리라벨 편향 감시.** 검수자는 프리라벨을 그대로 승인하는 경향이 있어, 수정률이 실제 오류율보다 낮게 나오고 재학습 데이터에 모델의 편향이 남는다. 이를 막기 위해 두 종류의 과제를 섞는다.

- **블라인드 과제:** 일정 비율(예: 3%)의 구간을 프리라벨 없이 배정한다. 같은 구간의 프리라벨 검수 결과와 비교해, 프리라벨이 결과를 얼마나 끌고 가는지 측정한다.
- **오류 삽입 과제:** 정답을 아는 구간에 경계 이동, 클래스 오류, 블러 누락을 의도적으로 넣어 배정한다. 검수자별 발견율을 측정해 교육과 배정에 반영한다. 삽입된 오류는 재학습 데이터에서 제외한다.

## 학습 루프와 지표

모든 자동 모델은 같은 루프를 따른다. 검수 승인 → 데이터셋 버전 커밋(자동 원본과 수정본의 차이 포함) → 일정 분량 누적 시 재학습 → 골든셋 평가 → 기존보다 나을 때만 배포.

**골든셋은 도메인별로 만든다.** 각 도메인의 첫 Phase(청소는 Phase 1, 요양돌봄은 Phase B, 간호는 Phase C)에서 사람이 처음부터 라벨링한 세션으로 만들고 학습에 절대 쓰지 않는다. 도메인 안에서는 작업 종류와 장갑·3인칭·IMU 유무 조합별로 고르게 포함한다.

**분할은 작업자·장소 단위로 한다.** 같은 작업자나 같은 장소(같은 집, 같은 화장실, 같은 병실)가 학습셋과 골든셋에 함께 들어가면 성능이 부풀려진다. 골든셋에 배정된 작업자와 장소의 세션은 학습·검증 분할에 넣지 않는다. 골든셋에는 일반화를 보기 위해 학습셋에 없는 작업자와 장소가 반드시 포함되도록 한다.

**골든셋 크기.** 도메인별 목표 시간과 클래스별 최소 표본 수(예: 원시 동작·파지 유형·상태 클래스마다 최소 30개 인스턴스)를 Gate 0에서 정한다. 최소 표본에 못 미치는 클래스는 해당 지표를 보고하되 배포 판정에서는 제외한다.

온톨로지 버전이 바뀌면 골든셋을 새 버전으로 이관하고 재검수한 뒤에만 평가에 쓴다. 버전이 섞인 골든셋으로는 모델 개선을 판정하지 않는다.

| 루프 | 재학습 데이터 | 핵심 지표 |
| --- | --- | --- |
| 블러 (얼굴·반사면·송장·문서·화면·사진물·주소) | 추가·삭제된 블러 영역 | 영상 1시간당 잔여 누락 건수(감사 기준), 자동 탐지 누락률, 오탐률 |
| 객체·도구 탐지 | 수정된 박스·클래스·작용부 마스크 | mAP, 검수자 수정률 |
| 손·전신 포즈 | 수정된 키포인트 | PCK, 수정 키포인트 비율 |
| 접촉·파지 | 장갑 정답 + 맨손 사람 라벨 + 수정 구간 | 접촉 시점 오차(ms, 장갑·맨손 분리), 파지 정확도, 도구-표면 접촉 F1 |
| 행동·단계 | 수정된 구간·클래스·상태 | 경계 오차, 구간 F1 |

골든셋 평가에는 위 핵심 지표와 함께 다음을 측정한다: 추적은 HOTA와 IDF1, 마스크는 IoU, 접촉은 정밀도·재현율·F1, 행동은 temporal mAP, 상태는 전이 정확도, 커버리지는 사람 라벨 대비 오차, 클래스 불균형은 macro F1, 3D 궤적은 3인칭 다시점 결과 대비 오차, 그리고 신뢰도 보정 오차(ECE). 보정 오차는 우선순위 큐와 표본 검증이 모두 모델 신뢰도에 의존하므로 반드시 본다.

운영 지표로는 영상 1시간당 검수 시간, 검수자 수정률, 자동 승인율(수정 없이 승인된 라벨 비율), 블라인드 과제 대비 프리라벨 편향, 오류 삽입 과제 발견율, 검증 에피소드당 생산원가를 매주 추적한다. 자동 승인율과 생산원가가 기술 개선을 사업성과 직접 연결한다. 자동 승인율이 오르는데 오류 삽입 발견율이 떨어지면 모델 개선이 아니라 검수 품질 저하로 본다. 검수 시간과 수정률이 줄지 않으면 모델보다 가이드라인이나 온톨로지에 문제가 있을 가능성이 높다.

**액티브 러닝.** 다음에 라벨링할 세션은 클래스별 검수자 수정률이 높은 작업·객체를 많이 담은 세션부터 고른다(예: 수정률 30%인 시트 접기가 0.5%인 컵 옮기기보다 먼저). 운영이 안정되면 불확실성, 모델 간 불일치, 신규성, 희소 클래스, 임베딩 다양성을 점수에 하나씩 추가하며, 처음부터 여러 항목의 가중합을 쓰지 않는다. 세션 선택과 세션 안의 검수 순서(검수 섹션의 우선순위 큐)는 별개이며, 블러 검수는 이 점수와 무관하게 종료 조건 전까지 전수 검수한다. 분석에는 FiftyOne을 쓴다.

## 데이터 거버넌스와 계보

모든 영상과 라벨은 상태 머신을 따라 한 방향으로만 이동하며, 어느 단계에서든 사용 중지 상태로 빠질 수 있다. 동의 철회나 삭제 요청이 오면 해당 영상이 어느 데이터셋 버전, 어느 학습 실행, 어느 내보내기에 들어갔는지 즉시 역추적할 수 있어야 한다.

1. 원본 수집
2. 프라이버시 승인
3. 프리라벨 완료
4. 사람 검증 완료
5. 분할 배정 (골든 / 학습 / 검증, 작업자·장소 단위)
6. 내보내기

| 계보 필드 | 붙는 대상 |
| --- | --- |
| 세션 ID, 원본 영상 ID, 촬영 일시 | 모든 데이터 |
| 작업자 ID (가명), 장소 ID (가명), 동의서 버전 | 세션 |
| 프라이버시 상태, 블러 검수자, 감사 여부 | 영상 |
| 라벨 버전, 온톨로지 버전, 검수자 ID, 검수 시각, 검증 상태 | 라벨 |
| 데이터셋 버전, 분할 | 라벨 묶음 |
| 학습 실행 ID, 모델 버전 | 데이터셋 버전 |
| 내보내기 이력 (대상, 일시, 형식, 검증 정책) | 데이터셋 버전 |

**사용 중지 처리.** 사용 중지된 영상은 이후 모든 데이터셋 버전과 내보내기에서 자동 제외된다. 이미 학습된 모델은 다음 정기 재학습에서 해당 데이터를 빼고 다시 학습하며, 즉시 폐기가 필요한 경우의 기준은 법무 검토로 정한다. 골든셋 세션이 사용 중지되면 골든셋 버전을 올리고, 이전 버전과의 지표 비교는 공통 세션만으로 다시 계산한다.

**보안과 보관.**

- 원본 영상·오디오는 저장 시 암호화하고, 원본 저장소는 라벨링 저장소와 분리한다.
- 원본 접근은 역할 기반으로 제한하고 모든 열람·다운로드를 감사 로그로 남긴다. 감사 로그는 월 1회 검토한다.
- 원본 보관 기간을 정하고(예: 블러본·라벨 확정 후 일정 기간), 기간이 지난 원본은 학습 필요 여부를 확인해 삭제하거나 연장 사유를 기록한다.
- 외부 라벨러는 웹 검수 도구로만 접근하게 하고, 영상 다운로드와 내보내기 권한을 주지 않는다. 화면에는 라벨러 ID 워터마크를 표시한다.
- 오디오는 동기화 계산용으로만 원본 저장소에 두고, 블러본과 배포본에서는 제거한다.

계보는 DVC 또는 lakeFS의 데이터 버전과 MLflow의 실행 기록을 세션 메타데이터 DB(PostgreSQL)에서 연결해 관리한다.

## 온톨로지 v1

온톨로지는 다섯 시간 계층(도메인 → 작업 → 하위 단계 → 원자 행동 → 손 상태)과 네 속성 사전(객체·도구, 대상자, 이벤트, 프라이버시)으로 구성한다. 모든 라벨은 온톨로지 버전 번호를 가진다.

기존 SOP가 없으므로 아래를 출발점으로 삼고, 파일럿 촬영 후 현장 전문가가 영상을 보며 구술한 설명으로 하위 단계를 정의한다.

| 도메인 | 작업 |
| --- | --- |
| 청소 | 바닥 쓸기·닦기, 표면 닦기·소독, 화장실 청소, 침상 정리·시트 교체, 쓰레기 수거·분리 |
| 요양돌봄 | 체위 변경, 이승 보조(침대↔휠체어), 식사 보조, 구강 위생, 기저귀 교체, 세면·목욕 보조, 옷 입히고 벗기기 |

### 원자 행동과 경계 규칙

원자 행동은 "동사(대상 객체 또는 신체 부위, 선택적 도구·방향)" 형태다. 동사는 통제 어휘이며, 로봇 학습의 추상화 층위(원시 동작 → 기술 → 작업)에 맞춰 나눈다. 라벨은 원시 동작 단위로 기록하고, 기술은 원시 동작 구간을 묶는 상위 구간이다. 아래 경계 규칙의 네 시각은 원시 동작에 적용한다.

| 층위 | 정의 | v1 어휘 |
| --- | --- | --- |
| 원시 동작 | 손과 대상 사이의 단일 물리 상호작용 | 잡다, 놓다, 들어 올리다, 내리다, 옮기다, 밀다, 당기다, 돌리다, 누르다, 문지르다, 지지하다 |
| 기술 | 원시 동작을 묶어 목표 상태를 만드는 단위 | 열다, 닫다, 닦다, 쓸다, 헹구다, 짜다, 뿌리다, 붓다, 펴다, 접다, 감싸다, 붙이다, 떼다, 끼우다, 빼다, 측정하다, 확인하다 |
| 기술 (사람 대상, Phase B부터) | 대상자 몸을 다루는 기술 | 굴리다, 일으키다, 눕히다, 들어 옮기다, 입히다, 벗기다 |
| 작업 | 작업 목록의 작업 | 화장실 청소, 침상 정리·시트 교체 등 |

도구를 쓰는 원시 동작(예: 걸레로 문지르다)은 대상에 도구가 작용하는 표면을 쓰고 도구는 선택 인자로 기록한다(예: "문지르다(세면대_02, 도구=걸레_12)"). 이때 손의 접촉 대상은 도구이고, 도구-표면 접촉은 관계 층에 따로 기록된다.

**경계 규칙(권장안 채택).** 행동 하나에 네 개의 시각을 기록한다. 구간은 접근 시작부터 종료까지이며, 접촉 시각은 구간 안의 별도 표시로 둔다. 로봇 학습에는 접촉 전 접근 궤적이 필요하고, 접촉 시각은 장갑으로 객관적으로 잡을 수 있기 때문이다. 모든 허용 오차는 ms 단위다.

| 시각 | 정의 | 허용 오차 |
| --- | --- | --- |
| 접근 시작 | 직전 행동 종료 후, 손이 목표를 향해 움직이기 시작한 첫 프레임 | ±200ms |
| 접촉 시작 | 손(도구 행동은 도구 작용부)이 목표에 처음 닿은 프레임 (장갑 있으면 압력 임계값) | 장갑 ±70ms, 영상 ±150ms |
| 접촉 종료 | 손(도구 행동은 도구 작용부)이 목표에서 떨어진 프레임 | 접촉 시작과 동일 |
| 종료 | 접촉 종료 후 손이 다음 목표로 향하기 직전 | ±200ms |

손별로 행동 트랙을 따로 두며, 양손이 함께 수행하는 행동(예: 굴리다)은 양손 트랙에 같은 행동 ID로 묶는다. 행동 사이 구간은 대기(의도적 정지), 미상(무엇인지 판단할 수 없음), 범위 외(대화, 기록 작성 등 조작이 아닌 활동) 중 하나로 채워 타임라인에 공백이 없게 한다. 미상 구간은 온톨로지 확장 후보로 매 버전 주기마다 검토하며, 모델이 모르는 구간을 대기로 처리하지 않는다.

**연속 접촉과 비접촉 행동.** 잡다 → 옮기다 → 놓다처럼 접촉이 이어지는 행동 묶음은 접촉 시작을 첫 행동에, 접촉 종료를 마지막 행동에만 기록하고 중간 행동은 "접촉 유지"로 표시한다. 중간 경계는 객체 상태나 운동 방향이 바뀌는 프레임으로 정한다. 걸레질처럼 도구를 쥔 채 표면 접촉이 반복되는 경우, 손-도구 접촉은 하나의 연속 구간으로, 도구-표면 접촉은 닿았다 떨어질 때마다 별도 구간으로 기록한다. 확인하다처럼 접촉이 없는 행동은 접촉 시각을 비운다. 손을 뻗는 동작은 모든 행동의 접근 구간에 포함되므로 별도 동사로 두지 않는다.

### 손 상태 (손별, 구간 단위)

손 상태는 값이 바뀌는 시각(변화점)과 그 사이 구간으로 기록한다. 프레임 단위 값은 내보내기 시 구간에서 생성한다.

| 속성 | 값 |
| --- | --- |
| 접촉 대상 | 없음, 객체(개체 ID), 도구(개체 ID), 대상자(신체 부위), 고정 표면, 자기 몸 |
| 파지 유형 | 전체 손 쥐기, 손가락 끝 집기, 옆면 집기, 갈고리 걸기, 손바닥 지지, 손바닥 밀기·닦기, 도구 쥐기, 비파지 접촉 |
| 역할 | 주동, 보조·고정, 비활동 |

### 대상자 사전

신체 부위는 좌우와 상하를 구분한 26개다: 머리, 목, 가슴, 복부, 등 상부, 허리, 좌·우 어깨, 좌·우 상완, 좌·우 팔꿈치, 좌·우 전완, 좌·우 손, 좌·우 둔부, 좌·우 대퇴, 좌·우 무릎, 좌·우 하퇴, 좌·우 발. 기저귀 교체 등 민감 부위는 둔부 범주로 기록하고 더 세분하지 않는다.

대상자 자세는 앙와위, 좌측와위, 우측와위, 복와위, 반좌위, 좌위(침대), 좌위(휠체어·의자), 입위, 보행 중으로 기록한다.

### 객체·도구 사전

객체마다 클래스, 개체 ID, 물리 유형, 상태 속성을 둔다. 물리 유형은 강체, 관절체(문, 서랍, 침대 난간), 변형체(시트, 수건, 의류, 기저귀), 액체·분말, 사람의 다섯 가지다. 상태 속성은 클래스별로 정의한다(예: 열림/닫힘, 펼침/접힘, 오염/깨끗함, 가득/빔, 착용/미착용, 젖음/마름). 행동마다 대상의 사전·사후 상태를 기록한다.

**도구** 클래스(걸레, 밀대, 솔, 스펀지, 스프레이, 빗자루 등)에는 추가로 작용부(걸레 헤드, 솔 끝, 스펀지 면, 분사구)와 파지부(손잡이)를 정의한다. 처리 대상 **표면**(바닥, 세면대, 변기, 거울, 탁자 등)에는 오염/깨끗함 상태와 커버리지를 둔다.

객체 클래스 목록은 파일럿 영상에서 출현 빈도 순으로 v1을 확정한다.

### 이벤트 사전 (실패·재시도·안전, 모두 포함)

| 범주 | 이벤트 | 기록 형태 |
| --- | --- | --- |
| 실패·재시도 | 파지 실패, 물체 놓침·낙하, 재파지, 행동 재시도, 단계 중단, 미처리 영역 재작업 | 시점 또는 구간 + 관련 행동 ID |
| 작업 안전 | 미끄러짐, 충돌, 날카로운 물체 접촉 | 구간 + 심각도(1~3) |
| 대상자 안전 | 균형 상실, 낙상 위험, 불편 반응(표정·움츠림·음성) | 구간 + 심각도(1~3) |
| 감염관리 | 장갑 미착용 상태로 체액·오염물 접촉, 오염 후 청결 표면 접촉, 오염 도구로 청결 표면 접촉 | 시점 + 관련 객체 |

### 자연어 설명

하위 단계마다 한 문장 지시문을 붙인다(예: "어깨와 골반을 받쳐 대상자를 왼쪽으로 돌려 눕힌다"). VLM이 초안을 쓰고 검수자가 고친다. VLA 모델 학습의 언어 입력으로 쓴다.

### 프라이버시 사전

v1 필수: 얼굴, 반사면 속 얼굴·사람, 택배 송장, 문서·우편물, 켜진 화면, 사진물, 주소 식별 정보(문패, 호실 번호). 확장 후보는 미결정 사항에서 확정한다.

상용화 가능성이 있다면 아래 "주의" 항목은 Phase 0에서 대체안을 확정한다. 라이선스는 도입 시점에 각 저장소에서 다시 확인한다.

**카메라 자세·깊이 후보.** 시각-관성 SLAM은 Basalt(BSD-3), ORB-SLAM3의 시각-관성 모드(GPL-3.0), 시각 SLAM은 DROID-SLAM(BSD-3)과 ORB-SLAM3, 단안 깊이는 Depth Anything V2가 후보다. Depth Anything V2는 Small 모델만 Apache 2.0이고 더 큰 모델은 비상업 라이선스다.

**로봇 학습 내보내기.** 내부 세션 스키마를 기준으로 두고 COCO(객체·키포인트), 시간 구간 JSON, 그리고 로봇 학습 프레임워크가 쓰는 에피소드 형식(예: LeRobot 데이터셋 형식)으로 변환하는 내보내기 모듈을 만든다. 에피소드에는 손 궤적과 함께 도구 작용부 궤적, 도구-표면 접촉 구간, 검증 상태를 포함한다.

## 자원 계획

Phase 0에서 아래 항목을 추정해 문서화하고, 분기마다 실측치로 갱신한다. 로드맵 기간은 이 계획의 팀 구성 가정을 따른다.

| 항목 | 추정 근거 |
| --- | --- |
| 목표 데이터량 | 도메인별 촬영 시간(시간) × 작업 종류 수, 골든셋 몫 별도 |
| 저장 용량 | 원본(해상도·비트레이트 × 시간) + 블러본 + 프록시 + 장갑·IMU 시계열 + 라벨, 데이터셋 버전 보관 배수 포함. 예: 1080p 45Mbps 원본은 시간당 약 20GB |
| GPU 예산 | 프리라벨 추론(영상 1시간당 모듈별 GPU 시간) + 정기 재학습 + VLM 추론 |
| 인력 | 원본 권한자(블러 검수·감사·표정 라벨), 일반 라벨러, QA 선임, ML 엔지니어, 플랫폼 엔지니어, 현장 촬영 담당 |
| 라벨 원가 | 영상 1시간당 단계별 검수 시간 × 인건비. 수동 라벨링(Phase 1) 실측치를 기준선으로 삼음 |
| 장비 | IMU 기록 바디캠, 촉각장갑, 3인칭 카메라, QR 슬레이트용 기기 |

## 단계별 로드맵

온톨로지를 먼저 동결하고, 학습 루프는 마지막에 닫는다. (청소 도메인 기준, 기간은 자원 계획의 팀 구성 가정에 따른 추정치)

| 단계 | 기간 | 주요 작업 |
| --- | --- | --- |
| Phase 0 · 준비 | 약 4~6주 | 온톨로지 v1 확정(도구·표면 포함), 라벨 가이드라인, 세션 스키마, 카메라 선정(IMU 기록 여부), 촬영 현장 프로토콜(QR 슬레이트), 파일럿 촬영·구술, 자원 계획, 성공 기준 잠정치, 라이선스·법무 검토 |
| **Gate 0** | | 온톨로지 v1 동결, 성공 기준 잠정치·골든셋 크기 목표 확정, 법무 검토 완료 |
| Phase 1 · 기반 | 약 6~8주 | 수집·동기화, 블러 자동화·검수·잔여 누락 감사, 검수 도구 연동, 수동 라벨링(라벨 원가 기준선 측정), 작업자·장소 단위 골든셋 구축(맨손 접촉 라벨 포함) |
| **Gate 1** | | 골든셋 완성, 검수 후 잔여 블러 누락률이 목표 이하, 성공 기준 수치 확정, 검수 도구 단일화 결정 |
| Phase 2 · 프리라벨 | 약 6~8주 | 객체·도구 추적, 손·전신 포즈, 접촉·파지·도구-표면 접촉 추정, 카메라 자세·깊이, 2단 행동 구간(경계 후보 + VLM 분류), 우선순위 큐, 블라인드·오류 삽입 과제 |
| **Gate 2** | | 영상 1시간당 검수 시간이 Phase 1 수동 기준선 대비 목표 비율 이상 감소, 오류 삽입 발견율이 기준 이상 유지 |
| Phase 3 · 루프 | 약 4~6주 | 재학습 자동화, 모델 레지스트리, 액티브 러닝, 로봇 학습 내보내기, 전용 탐지기 전환, 블러 전수 검수 종료 조건 판정 |

수동 라벨링을 Phase 1에 먼저 해봐야 가이드라인의 모호한 점과 동기화 문제가 드러나고, 이때 만든 골든셋과 라벨 원가 기준선이 이후 모든 모델 평가와 Gate 2 판정의 기준이 된다. Phase 3 이후에는 데이터 규모 확대를 결정한다.

**도메인 확장 순서.** 위 로드맵은 청소 도메인 기준이다. 청소에서 Gate 2를 통과한 뒤 요양돌봄(Phase B), 이어서 간호(Phase C)로 넓히며, 각 도메인은 작업 목록 확정 → 도메인 골든셋 구축 → 프리라벨 → 루프 순서를 다시 밟고, 블러는 전수 검수부터 다시 시작한다. 요양돌봄으로 넘어가기 전에는 요양 영상 소량으로 블러 파이프라인과 대상자 사전(신체 부위, 자세)을 먼저 검증하고, 표정 라벨 패스를 활성화한다. 요양 영상은 대상자 얼굴과 신체 노출이 많아 프라이버시 위험이 청소와 다르기 때문이다. 간호로 넘어가기 전에는 촉각장갑 착용 가능 여부를 확인한다.

## 미결정 사항

- [ ] 프라이버시 확장 대상(약봉투, 팔찌, 명패, 의료 차트, 명찰, 메모) 중 v1 포함 범위
- [ ] 비식별화한 오디오를 별도 제공할지 여부 (기본값은 배포본에서 오디오 제거)
- [ ] 상용화 여부와 그에 따른 라이선스 대체안
- [ ] 원본 영상으로 학습하는 것에 대한 수집 동의서 문구와 법무 검토
- [ ] 바디캠 기종(IMU 기록 지원 여부 포함)
- [ ] 촉각장갑 기종, 센서 수, 샘플레이트, 외형(맨손과의 차이)
- [ ] 객체·도구 클래스 v1 목록(파일럿 출현 빈도 기준)
- [ ] 작업별 하위 단계 목록(현장 전문가 구술 기반)
- [ ] 검수 도구를 CVAT·Label Studio 하이브리드로 유지할지 단일화할지 (Gate 1)
- [ ] 성공 기준 수치(검수 시간, 잔여 블러 누락 상한, 일치도 기준): Gate 0 잠정, Gate 1 확정
- [ ] 골든셋 도메인별 목표 시간과 클래스별 최소 표본 수 (Gate 0)
- [ ] 블러 전수 검수 종료 조건의 기간과 감사 표본 비율
- [ ] 블라인드·오류 삽입 과제 비율
- [ ] 원본 보관 기간
- [ ] 자원 계획의 팀 구성 가정과 예산
- [ ] 대상 로봇 학습 프레임워크와 내보내기 형식

## 개정 이력

- 2026-10-07 개정
  - 동기화: NTP·PTP 대신 QR 시각 슬레이트를 기본으로 함. 장갑의 오디오 없는 경우의 동기화 경로를 명시함.
  - 스트림: 바디캠 IMU를 선택 스트림으로 추가함. 카메라 선정 기준과 시각-관성 SLAM을 반영함.
  - 스키마: 도구 작용부, 도구-표면 접촉, 표면 커버리지를 추가함.
  - 블러: 반사면, 문서·우편물, 켜진 화면, 주소 식별 정보를 v1 필수 대상으로 추가함. 배포본 오디오를 기본 제거함.
  - 블러 지표: 검수 후 잔여 누락을 표본 감사로 측정함. 전수 검수 종료 조건을 정의함.
  - 접촉 모델: 장갑·맨손 분포 차이 대응(맨손 라벨, 분리 지표, 쌍 세션)을 추가함.
  - 행동 구간: 경계 후보 생성 + VLM 분류의 2단 구조로 변경함.
  - 검수: 단계 수를 정정함. 표정 라벨을 별도 패스로 분리함. 블라인드·오류 삽입 과제를 추가함.
  - 골든셋: 도메인별 구축, 작업자·장소 단위 분할, 크기 목표를 추가함.
  - 시간 단위: 블러 유지 시간과 경계 허용 오차를 ms로 통일함. 손 상태를 구간 단위로 확정함.
  - 검증 상태에 "표본 검증"을 추가하고 내보내기 검증 정책을 정의함.
  - Gate 기준을 정량화하고 자원 계획과 보안·보관 항목을 추가함.
