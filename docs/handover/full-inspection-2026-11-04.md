# 전수 검사 2026-11-04: 저장소 전체 (9979b90)

pstack swarm·interrogate 방식으로 저장소 전체를 10개 구역으로 나눠 검사했다. 실행으로 증명한 결함만 남겼고,
고치는 일은 검사가 끝난 뒤 패키지 경계로 나눈 8개 묶음으로 따로 했다. 결정 기록은
[decisions/2026-11-04-pstack-overhaul.tsv](decisions/2026-11-04-pstack-overhaul.tsv)에 있다.

## 방법

- 구역: s1 계약·DB, s2 미디어·동기화, s3 프라이버시, s4 프리라벨, s5 검수, s6 행동·관계·AI 검수,
  s7 데이터셋·내보내기·리타기팅, s8 학습·평가·모델·액티브, s9 CLI·콘솔·운영·스크립트, s10 패키지를 가로지르는 종단 흐름.
- 구역마다 독립 검사자가 저장소를 고치지 않고 코드를 읽었다. 재현은 합성 픽스처, 일회용 DB(`dlp_test_*`),
  실제 Label Studio·SeaweedFS·lakeFS로 돌렸다. 지적마다 실행 명령, 실제 출력, 의도대로라면 나와야 할 출력을 적었다.
- 취합 단계에서 조정자가 모든 재현을 다시 돌렸다. 같은 출력을 다시 얻은 것만 등록했다(신규 지적 21건과 기존 3건, 모두 재현).
- 돌려서 증명하지 못한 의심(구역마다 최대 5건)은 등록하지 않았다.
- 같은 원인 둘은 한 ID로 합쳤다: 콘솔 결과 보기의 사용 중지 세션(s9)과 무효 렌더(s3)는 F-COE-85.

## 운영에 미치는 영향

- 트래커 버전이 iou-tracker-3으로 바뀌어 다음 `dlp privacy detect`가 기존 세션을 다시 탐지한다. 새 블러 라벨은
  다시 블러 검수·승인을 받아야 렌더된다.
- 행동·설명 모델 버전에 온톨로지 부분 해시(`+o<8자>`)가 붙어, 다음 `dlp actions run`과 설명 재생성이 기존 세션을
  한 번 다시 돈다 (검수된 라벨은 보호).
- verify는 이제 손 타임라인 빈 시간이 있으면 완료를 막는다. 검수자는 검수 도구에서 행동이나 공백으로 채운다.

## 남은 판단

- F-PAR-87: 3D 보호 판정은 아직 (개체, 부위, 좌표계) 기준이라, 사람이 직접 검수한 옛 3D와 같은 번호인 새 물체 3D는
  막힌다. 지금은 3D 검수 화면이 없어 드물다.
- F-ETA-31: 같은 ID로 두 빌드가 동시에 돌면 확인을 둘 다 통과할 수 있다.
- 검수가 끝나지 않은 세션도 데이터셋 후보다(ADR 0031). 기본 내보내기는 미검수 라벨을 빼므로 그대로 둔다.
