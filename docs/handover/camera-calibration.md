# 카메라 내부 파라미터·작업자 손 크기 등록 절차 (운영자용)

기준: ADR 0045, 0052. 손가락 끝 3D(ADR 0044)는 바디캠 내부 파라미터(초점 거리·주점)와 손 크기 사전값으로
거리를 정한다. 둘 다 없으면 가로 화각 90도 근사와 성인 평균 손바닥 0.09 m를 쓰고, 3D 표본 신뢰도가
낮게(`intrinsics=hfov_approx`) 기록된다. 이 문서는 기기마다 한 번, 작업자마다 한 번 하는 등록 절차다.

## 1. 기기 ID 정하기

- 바디캠 한 대에 ID 하나 (예: 일련번호 `gopro-c3471325`). 영숫자로 시작, 영숫자와 `_ . : -`, 128자 이하.
- 같은 기기라도 해상도·화각 모드(예: Wide/Linear)·렌즈 모듈을 바꾸면 내부 파라미터가 달라진다. 촬영
  모드는 세션 내내 고정하고, 모드가 다르면 다른 ID로 관리한다 (예: `gopro-c3471325-linear-4k`).
- 수집 매니페스트에 기기 ID를 적는다. 내부 파라미터를 직접 적었으면(`calibration.intrinsics`) 그 값이
  등록보다 앞선다.

```yaml
calibration:
  camera_id: gopro-c3471325-linear-4k
```

- 이미 수집한 세션(매니페스트에 `camera_id`가 없던 세션, ADR 0045 이전 수집 포함)은 매니페스트를 고쳐 다시
  수집하지 않는다 (세션 내용이 달라 `SessionConflictError`). 대신 기기에 잇는다 (추가 전용
  `session_camera_assignments`, 매니페스트에 다른 기기가 있으면 거부):

```bash
dlp calib assign gopro-c3471325-linear-4k s001 s002 --reason "촬영 기록부 2026-09"
dlp calib assign gopro-c3471325-linear-4k --worker w01 --since 2026-09-01T00:00:00+09:00 \
  --until 2026-10-01T00:00:00+09:00 --reason "w01 9월 촬영분"
dlp calib show --session s001     # 지금 쓰는 내부 파라미터 출처(registry:…)와 연결 기록
```

## 2. 체커보드 영상 찍기

준비물: 평평한 판에 붙인 체커보드 인쇄물. 안쪽 코너 수(예: 9x6 칸이면 안쪽 코너 8x5)를 센다. 칸 한 변
(`--square-mm`)은 명령 인자로만 필요하고 내부 파라미터에는 영향이 없다 (보드 전체가 같은 비율로 크거나
작아도 결과는 같다). 대신 칸이 정사각형이어야 한다: 가로·세로를 각각 재서 1% 안으로 같은지 확인하고
(프린터가 한 방향으로 늘이면 fx·fy가 어긋난다), 판이 휘지 않게 한다. 결과를 좌우하는 것은 보드
기울기·위치의 다양성(아래 3번), 초점·움직임 흐림이다.

1. 세션과 같은 촬영 모드·해상도로 찍는다. 손떨림 보정(전자식 안정화)은 끈다 (프레임마다 내부
   파라미터가 바뀐다). 세션도 같은 설정이어야 한다.
2. 보드만 찍는다. 사람 얼굴·서류·화면이 들어오지 않게 한다 (이 영상은 원본 버킷에 올리지 않고 로컬
   파일로 다룬다).
3. 보드를 화면 가운데·네 모서리·가장자리로 옮기고, 앞뒤·좌우로 20~40도 기울인 자세를 15개 이상
   찍는다. 기울이지 않고 옮기기만 하면 초점 거리가 정해지지 않는다 (재투영 오차가 작아도 10배 넘게
   틀린 값이 나온다. 명령이 기울기 부족으로 거부한다). 자세마다 0.5초 이상 멈춘다 (움직임 흐림 방지). 보드가 화면의 1/4 이상을 채우게 가깝게.
4. 조명은 고르게, 반사(광택 인쇄)를 피한다.

## 3. 등록

```bash
# 결과만 보기 (DB에 쓰지 않음)
dlp calib intrinsics gopro-c3471325-linear-4k board.mp4 --board 8x5 --square-mm 30 --dry-run
# 등록
dlp calib intrinsics gopro-c3471325-linear-4k board.mp4 --board 8x5 --square-mm 30
```

- 종료 코드 2: 보드 장면 부족(`calibration.yaml intrinsics.min_views`), 재투영 RMS 초과
  (`max_rms_px`), 보드 기울기 부족(`min_max_view_tilt_deg`, "기울인 자세가 부족"), 타당 범위 밖(가로
  화각·주점·fx/fy 비·왜곡 계수). 코너 수를 다시 세고, 기울인 자세를 늘려 다시 찍는다. 먼저
  `--dry-run`으로 확인하는 것을 권한다.
- 출력의 fx·fy가 서로 1~2% 안이고 cx·cy가 화면 가운데 근처인지 본다. 재투영 RMS는 보통 0.2~0.5 px다.
- 같은 결과를 다시 등록하면 쓰지 않는다 (멱등).
- 제조사·다른 도구로 이미 아는 값은 파일로 가져온다: `dlp calib import <기기> cam.yaml`
  (이 저장소 형식 `width, height, fx, fy, cx, cy, distortion`, OpenCV FileStorage, ROS camera_info).
  같은 값 검사를 한다. 파싱 오류·모르는 키, ROS 미보정 파일(K가 모두 0), 어안(`equidistant` 등) 왜곡
  모델, 음수·nan·화면 밖 주점은 종료 코드 2로 거부하고 등록하지 않는다.
- 렌즈·촬영 모드를 바꾸면 `--valid-from 2026-11-01T00:00:00+09:00`으로 새로 등록한다. 그 시각
  이후 녹화한 세션만 새 값을 쓰고, 예전 세션은 예전 값을 쓴다. 등록은 지우거나 고치지 않는다 (추가
  전용 DB 표 `camera_calibrations`).
- 잘못 등록한 값 바로잡기: `dlp calib show --camera <기기>`에서 그 등록 ID를 찾아
  `--supersede <등록 ID>`로 올바른 값을 다시 등록한다 (그 등록의 유효 시작을 그대로 쓴다. 같은 유효
  시작에서는 나중 등록이 앞선다). 유효 시작 없는 등록은 유효 시작 있는 등록을 이기지 못하고, 더 늦은
  시각으로 등록하면 그 사이 녹화 세션은 예전 값을 계속 쓴다. 새 등록이 가려지면 명령이 `[주의]`로
  알린다.
- 확인: `dlp calib show --camera gopro-c3471325-linear-4k` (`*`가 지금 시각 기준으로 쓰이는 값).

## 4. 작업자 손 크기

손목 주름 가운데에서 가운데 손가락 뿌리 관절(손등 쪽 너클)까지를 자로 잰다 (m, 보통 0.075~0.10).

```bash
dlp calib palm w01 0.084
dlp calib show --worker w01
```

세션이 하나도 없는 작업자 ID는 오타로 보고 거부한다 (종료 코드 2). 첫 녹화 전에 재서 등록하는 경우만
`--allow-unknown-worker`를 붙인다.

잰 값이 없으면 캘리브레이션된 세션에서 추정할 수 있다 (깊이 모델 가중치 필요, `make export-models`).
원본 바디캠을 읽으므로 감사 기록 `calib.palm_estimate`이 남는다.

```bash
dlp calib palm-estimate w01                   # 보고만 (표본 수·세션 수·중앙값, 지금 값)
dlp calib palm-estimate w01 --apply           # estimated로 등록 (표본을 낸 세션 ID도 남는다)
dlp calib palm-estimate w01 --reviewed-only   # 승인·표본 검증한 손 트랙만 (손 트랙 검수 뒤 권장)
```

- 사용 중지 세션, 원본 삭제 결정 세션, 캘리브레이션 없는 세션, 손 3D 점(world)이 있는 손 트랙이 없는
  세션, 원본이 없는 세션은 원본을 읽지 않고 건너뛴다 (감사 기록도 남지 않는다).
- 종료 코드: 3 세션 없음·표본 부족(`prelabel.yaml palm_estimate.min_samples`, 등록하지 않음), 4 지금
  잰 값이 쓰이고 있음(덮으려면 `--override-measured`), 5 추정 중 출처 세션이 사용 중지됨(다시 실행).
- 추정값은 깊이 모델의 배율 오차를 그대로 담는다. 잰 값이 있는 작업자에게는 `--apply`를 쓰지 않는다
  (명령이 거부한다). 출처와 관계없이 유효한 등록 중 가장 늦은 것이 쓰인다 (`dlp calib show --worker`의
  `*`).
- MediaPipe 손 트랙은 착용자 손과 다른 사람(돌봄 대상자) 손을 구분하지 않는다. 대상자 손을 잡는 장면이
  많은 작업자는 추정이 치우칠 수 있으므로 잰 값을 우선하고, 추정은 손 트랙 검수 뒤 `--reviewed-only`로
  돌린다.

### 손 크기 무효 (동의 철회·삭제 요구·잘못 잰 값)

등록은 지우지 않고 무효 기록을 더한다 (추가 전용 `worker_hand_size_invalidations`, ADR 0052). 무효가 된
등록은 3D에 쓰이지 않고, 남은 유효 등록 → 정책 기본값으로 돌아간다. 무효 뒤 새로 등록한 값은 다시
쓰인다.

```bash
dlp calib palm-revoke w01 --reason "동의 철회 2026-10-19 요청 #12"        # 그 작업자의 모든 등록
dlp calib palm-revoke w01 --record palm-1a2b3c4d5e6f --reason "잘못 잼"   # 등록 하나
```

- 추정 등록은 표본을 낸 세션을 기억한다. 그 세션을 `dlp dataset withdraw`로 사용 중지하면 그 추정은
  자동으로 쓰이지 않는다 (`dlp lineage <세션>`의 "손 크기 추정 출처"). 0052 이전 추정은 출처가 없으므로
  필요하면 `--record`로 무효로 하고 다시 추정한다.
- `dlp ops retention`은 세션이 모두 사용 중지된 작업자의 지금 쓰이는 손 크기를 `[손 크기]`로 알린다.
- 행(가명 작업자 ID와 손바닥 길이)은 물리적으로 남는다. 완전 삭제가 필요하면 별도 절차가 필요하다
  (ADR 0052 남은 결정).
- 작업자 ID는 DB에만 남고 내보내기에는 들어가지 않는다. 3D 모델 버전에는 사전값 출처
  글자(`+hpw` 작업자, `+hpp` 정책)만 남는다.

## 5. 반영

등록·기기 연결·손 크기 무효 뒤 세션마다 프리라벨을 다시 돌린다. 3D 단계 입력 해시가 바뀌어 검수 전 3D만 새 값으로 다시
만든다. 직접 승인·표본 검증한 3D는 그대로 남고, 같은 (개체, 부위)의 새 궤적은 만들지 않는다 (CLI
`[3D 보호]`). 2D 손·박스 트랙 승인으로 검수를 물려받기만 한 3D(ADR 0048)는 새 값으로 다시 만든 3D가
대신하고, 새 3D가 같은 2D 검수를 물려받는다 (ADR 0051, 사람이 다시 볼 것이 없다). 캘리브레이션 화면비가
영상과 다르면(다른 촬영 모드) 쓰지 않고 화각 근사로 떨어지므로 촬영 모드마다 기기 ID를 나눠 등록한다.

```bash
dlp prelabel run <세션>
```

새 3D 라벨의 페이로드 `intrinsics`가 `calibrated`, 표본의 `method`가 `hand_fit`이면 반영된 것이다.

## 한계

- 핀홀 + OpenCV 왜곡 모델만 다룬다. 어안 렌즈(초광각 모드)는 `cv2.fisheye`가 필요하다 (가져오기는
  어안 모델 파일을 거부한다). 왜곡 계수는
  등록만 하고 3D 단계는 아직 쓰지 않는다 (F-PAR-28). 광각 모드에서는 화면 가장자리 손의 3D가 틀릴 수
  있다.
- 카메라-IMU 외부 파라미터(SLAM용)는 이 절차에 없다 (F-PAR-26).
