# 촬영 가이드 (1인칭 돌봄·가사 영상)

첫 실영상 파일럿(2026-10-22, [pilot-real-2026-10-22.md](pilot-real-2026-10-22.md))에서 프리라벨 품질을 가장 많이
떨어뜨린 것은 모델이 아니라 촬영 조건이었다: 렌즈를 몰라 3D 거리가 틀렸고(초광각인데 기본 화각 90도),
방향 태그가 장착 방향과 달랐고(F-PMS-33), 30 fps라 빠른 손이 흐렸고, IMU가 없어 카메라 자세를 만들 수 없었다.
아래 조건을 지키면 같은 모델로도 결과가 좋아진다. `dlp media prepare`·`dlp ingest`가 점검할 수 있는 항목은
경고로 알린다(막지 않는다, 기준은 `config/policies/media.yaml capture`, 코드 `dlp_media.capture_check`).

## 1. 기기와 렌즈

| 할 것 | 이유 | 자동 점검 |
| --- | --- | --- |
| 기기·렌즈·해상도·fps 조합마다 기기 ID를 하나 정해 매니페스트 `calibration.camera_id`에 적는다 (예: `gopro12-wide-2.7k60`, `iphone13-ultrawide-0.5x-1080p60`) | 3D 단계가 그 기기의 등록 캘리브레이션을 쓴다 (ADR 0045). 없으면 화각 근사로 떨어져 거리가 수십 % 틀린다 | `no_device` |
| 한 세션 안에서 렌즈를 바꾸지 않는다 (스마트폰 0.5x/1x 전환, 디지털 줌 금지) | 내부 파라미터가 세션 하나에 하나다 | - |
| 렌즈 왜곡 보정 모드(선형/Linear 등)는 기기 ID에 포함해 고정한다 | 같은 렌즈도 보정 모드가 다르면 다른 카메라다 | - |
| 손떨림 보정(전자식 안정화, HyperSmooth, 액션 모드)을 끈다 | 프레임마다 자르기·회전이 달라져 내부 파라미터가 흔들리고 IMU와 화면이 어긋난다 | - |
| 기기 ID마다 체커보드 영상을 한 번 찍어 등록한다 (`dlp calib intrinsics`, 절차 [camera-calibration.md](camera-calibration.md)) | 손 3D·접촉·리타기팅이 모두 이 값에 의존한다 | - |

## 2. 프레임레이트·노출

| 할 것 | 이유 | 자동 점검 |
| --- | --- | --- |
| 60 fps (최소 50 fps) | 30 fps에서는 빠른 손동작이 흐려져 손 검출이 끊긴다 (파일럿 손 존재 약 78%) | `low_fps` |
| 고정 프레임레이트 | 가변이면 보간 간격이 고르지 않다 (오류는 아님, 시각은 PTS로 계산) | `variable_fps` |
| 노출·화이트밸런스 고정 (노출 잠금, 가능하면 셔터 1/250 s 이상) | 자동 노출이 흔들리면 같은 물체의 색·밝기가 바뀌어 추적이 끊기고, 느린 셔터는 움직임 흐림을 만든다 | - |
| 젖은 손·스테인리스 반사가 많은 장면은 조명을 고르게 | 반사가 손·얼굴 오탐을 만든다 (F-PMS-31) | - |

## 3. 장착

| 할 것 | 이유 | 자동 점검 |
| --- | --- | --- |
| 장착 위치(가슴·머리)와 방향을 세션마다 같게, 매니페스트 `calibration.mount_position`에 적는다 | 손이 화면 아래쪽에서 들어오는 바로 선 가로 화면을 기준으로 정책을 맞췄다 | `portrait` |
| 거꾸로·옆으로 달았으면 수집 전 `dlp media prepare --display-rotation`으로 바로 세운다 | 스마트폰 방향 고정 태그가 실제 장착과 다를 수 있다 (F-PMS-33) | `rotation_tag` |
| 두 손과 작업면이 함께 보이게 약간 아래로 기울인다 | 손이 화면 밖으로 자주 나가면 손 트랙이 끊긴다 | - |

## 4. 시작과 길이

| 할 것 | 이유 | 자동 점검 |
| --- | --- | --- |
| 녹화 시작 뒤 1초 이상 몸을 멈춘다 | IMU 자이로 바이어스·중력 방향을 추정한다 (ADR 0046) | `no_still_start` |
| 여러 스트림(3인칭·장갑)이면 시작 때 QR 슬레이트나 손뼉 두 번 | 동기화 기준 (`dlp sync run`) | - |
| 세션은 30분 이내로 나눈다 | CPU 프리라벨 시간(OWLv2는 영상 길이의 약 15배)과 검수 단위 | `long_session` |

## 5. 카메라 자세가 필요하면 IMU가 있는 카메라

바디캠 6자유도 자세·월드 좌표 3D·리타기팅의 손 궤적은 IMU가 있어야 만든다. GoPro(GPMF 내장 IMU)를 권장한다.
스마트폰 기본 카메라 앱 영상에는 IMU 트랙이 없다(`no_imu`). 다른 기기는 같은 시계의 IMU 사이드카
(CSV/Parquet, 열 `t_ms, ax, ay, az, gx, gy, gz`)를 매니페스트에 넣는다.

## 6. 개인정보

촬영 전 동의와 현장 권한을 확인한다. 거울·창·스테인리스 반사, 택배 송장, 화면, 문서, 사진은 블러 대상이다.
촬영 범위에서 치울 수 있는 것은 치운다(프라이버시 오탐·누락이 모두 준다). 원본 영상과 그 이미지를 저장소에
넣지 않는다.

## 7. 수집 때 보는 경고

```
$ uv run dlp media prepare 원본.mp4 --out prepared.mp4 --display-rotation 180
준비 완료: prepared.mp4 1920x1080, 회전 0° (적용: 지정 180°), PTS 보존
경고[low_fps]: 프레임레이트 30.0 fps < 권장 50 fps (손 흐림·끊김)
$ uv run dlp ingest session.yaml
...
경고[no_imu]: IMU 없음: 바디캠 자세·월드 좌표 3D를 만들 수 없다
```

경고가 있어도 수집은 된다. 같은 장비로 다음 촬영을 고칠지 판단하는 데 쓴다.
